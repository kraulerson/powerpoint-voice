# Design Note — Voice Engine (Vosk + microphone)
**Status:** DESIGNED, NOT IMPLEMENTED. Deferred by Orchestrator decision 2026-08-04 so that
F7 (presentation UI) + F6 (keyboard parity) ship first — every voice failure path in this
design terminates in a keyboard fallback that did not yet exist, and 6 days before the talk
there was no usable presenter at all (BUG-18).
**Provenance:** produced by an 8-agent design workflow (4 parallel API/codebase/packaging
deep-dives -> synthesis -> 3 adversarial critics). All three critics returned NEEDS_CHANGES;
their findings are recorded below and MUST be folded in before implementation.

---

## 1. Architecture (as designed)
VOICE ENGINE (branch walk/voice-engine) — the IRecognizer implementation. Design principle: the engine is a THIN I/O shell wrapped around a THICK pure core. Every decision that can be made without a microphone or the 40MB model is made by a pure function in pptv_core and unit-tested; the shell in pptv_voice does nothing but move bytes and call those functions.

TARGET SPLIT (this is the enforcement mechanism, not a convention):
- pptv_core (existing) gains src/voice/*.{hpp,cpp} for the PURE half. pptv_tests links ONLY pptv_core + doctest, exactly as today.
- pptv_voice (NEW static lib) holds the Vosk + miniaudio + CoreAudio code and links Vosk::vosk. pptv_tests must NEVER link it. Because tests cannot link libvosk, it is mechanically impossible for a unit test to open a device or load a model — the hard constraint becomes a build-graph property.

THREE THREADS, ONE HOP EACH WAY:

1. Real-time audio thread (CoreAudio AudioUnit render thread on macOS; miniaudio's ma_worker_thread on ALSA/Pulse). MiniaudioCapture::onAudio does four things and nothing else: memcpy frameCount int16 frames into a ma_pcm_rb (SPSC lock-free, 2 s = 32000 frames); compute peakAmplitude() over the chunk into a std::atomic<int>; stamp a std::atomic<qint64> lastCallbackMs; bump an atomic overrun counter if acquire_write returns short (DROP, never block, never seek the read pointer). The whole body is wrapped in try/catch(...) because the callback is a C function pointer and an escaping C++ exception is UB. No allocation, no mutex, no logging, no Vosk. miniaudio is configured capture.format=ma_format_s16, capture.channels=1, sampleRate=16000, periodSizeInMilliseconds=20 (=> a constant 320-frame callback), resampling.linear.lpfOrder=8 (we decimate 48k->16k 3:1; the default 4th-order LPF folds aliases straight into the speech band).

2. Recognition worker (std::jthread, normal priority, owned by VoskRecognizer). Blocks on a 10 ms timed wait, drains the ring in chunkSamples(16000,200) = 3200-sample units, and calls vosk_recognizer_accept_waveform_s(rec, samples, sampleCount). Return value drives everything:
   r==1 -> const char* raw = vosk_recognizer_result(rec); the VERY NEXT STATEMENT is const QByteArray json(raw) — a deep copy, because raw points into the recognizer's last_result_ std::string and is invalidated by the next result()/reset()/free(). Then std::optional<QString> p = finalizedPhrase(json) (PURE). If p, pump_.deliver(*p).
   r==0 -> nothing. vosk_recognizer_partial_result is NEVER CALLED — the symbol is not referenced anywhere in src/, which makes contract #1 structurally impossible to violate rather than filtered at runtime. A CI grep enforces that.
   r==-1 -> a swallowed internal exception. Do NOT call result(). Call vosk_recognizer_reset() inside try/catch, feed DecodeErrorBudget; when exhausted, post VoiceEvent::DecodeErrorBudgetExhausted -> state Failed -> visible "voice degraded, use the clicker".
   Every unwrapped Vosk call (result/reset/find_word) is individually try/catch(...)'d — those are not exception-wrapped in vosk_api.cc and a KaldiFatalError would escape through the C ABI and std::terminate the worker.

3. Qt GUI thread. Owns RecognizerController (state_ is non-atomic) and PhrasePump. PhrasePump::deliver() is callable from any thread and does QMetaObject::invokeMethod(this, ..., Qt::QueuedConnection, Q_ARG(QString, phrase)) — an OWNING QString crosses the hop, never a const char*. The pump invokes the handler (controller.onPhrase) on its own thread, exactly once per delivery, in order, and swallows handler exceptions.

STARTUP SEQUENCE (VoskRecognizer, all off the GUI thread except step 1):
1. MicPermission gate on the GUI thread (macOS): Qt's QMicrophonePermission in the GUI app, with an AVCaptureDevice .mm shim as the fallback and as the only path for the headless voice_probe. Undetermined -> request; Denied -> VoiceState::PermissionDenied, a blocking actionable screen, and NO device is opened. Granted -> continue.
2. resolveModelPath(env, appDirPath, buildTreeDir, probe) then inspectModelLayout(dir) — PURE, both. Layout must be Ok: am/final.mdl + conf/model.conf + graph/HCLr.fst + graph/Gr.fst present AND graph/HCLG.fst absent. An HCLG model would make vosk_recognizer_new_grm silently build a FULL ~200k-word unconstrained decoder with only a stderr warning. Missing/Incomplete/NotGrammarCapable -> VoiceState::ModelMissing, never a NULL into vosk_model_new.
3. vosk_set_log_level(-1) once from the main thread BEFORE vosk_model_new (Vosk only installs its filtering handler inside Model's ctor). This is a Bible section 8 control, not cosmetics.
4. Worker thread: vosk_model_new(absolute inner dir). Null-check. ~0.5-3 s, ~62 MB of reads — never on the GUI thread; UI shows Loading.
5. Pre-flight: checkVocabulary(grammarVocabulary(), [&](w){ return vosk_model_find_word(model, w.toUtf8().constData()) != -1; }). Any missing token is a hard fail with the token named, because vosk_recognizer_new_grm SILENTLY DROPS out-of-vocabulary grammar tokens with only a KALDI_WARN — a dropped "resume" means the presenter cannot escape Paused mid-talk.
6. const QByteArray g = buildGrammarJson(); assert validateGrammarJson(g) == GrammarDefect::None BEFORE the call. A payload that is not a non-empty JSON array of strings leaves decode_fst_ null and vosk_recognizer_new_grm then dereferences it — a SEGFAULT, not a NULL return, and the try/catch(...) does not save you. Verified: this model has no HCLG.fst, so the null branch is the live branch.
7. vosk_recognizer_new_grm(model, 16000.0f, g.constData()). Null-check. No set_words / set_partial_words / set_max_alternatives calls at all — the defaults are what we want and the simplest correct thing is to call none of them. vosk_recognizer_set_grm is NEVER called: verified by nm on the vendored macOS binary that _vosk_recognizer_set_grm is NOT exported (the header is v0.3.45, the macOS lib is 0.3.44) — it would build green on Ubuntu CI and fail on the Apple-Silicon showtime machine.
8. Warm-up: feed ~1 s of silence through accept_waveform_s so the first real command does not pay the nnet3 compile cost.
9. Start order: worker FIRST, then ma_device_start — otherwise the ring fills with no consumer and the first seconds are lost.

SHUTDOWN (order is load-bearing): ma_device_stop() first, from the GUI thread — its return is the ONLY guarantee no callback is in flight. Then disable the pump (so a queued phrase cannot fire a slide command after the presenter said stop), then join the worker, then vosk_recognizer_free, then vosk_model_free, then ma_device_uninit, then ma_pcm_rb_uninit. ma_device_uninit deliberately does NOT stop the device (the stop-first code is #if 0'd out), so uninit-without-stop is a use-after-free on CoreAudio. vosk_recognizer_final_result is called at most once and its result is DISCARDED.

DEGRADE-SAFE SURFACE: a pure VoiceState machine (Idle, PermissionRequired, PermissionDenied, ModelMissing, Loading, Listening, Muted, DeviceLost, Failed, Stopped) with nextState(state,event), isListening(state) true for EXACTLY ONE state, and voiceStateMessage(state) non-empty and actionable for every other. The UI's listening glyph is derived from isListening() alone, so "silently pretending to listen" is not representable. Driven by: the permission gate, the model layout check, the decode error budget, and a 1 Hz GUI-thread watchdog that reads ma_device_get_state() plus the two atomics and feeds SilenceWatchdog. That watchdog is the ONLY detector for the three failure modes that all return MA_SUCCESS and deliver zeros forever — denied TCC permission, a hardware mute, and miniaudio's silent null-backend fallback (mitigated additionally by MA_NO_NULL and an assert that the negotiated backend is not ma_backend_null). Device unplug fires NO notification on either target platform (CoreAudio's on_start_stop swallows it with a standing TODO; ALSA/Pulse only post stopped when stopping SUCCEEDS, which it does not on unplug), so polling is mandatory, not belt-and-braces.

GRAMMAR-CONSTRAINED, TWO LOAD-BEARING LAYERS: Vosk grammar mode is a bigram LM (ngram_order=2, discount=0.5), NOT an exact phrase matcher — it can emit cross-phrase sequences like "next presentation". It is a strong SOFT vocabulary constraint. The HARD guarantee that only the five commands ever move the deck stays where it already is: matchCommand's closed phrase-level grammar. Both layers are load-bearing and neither may be relaxed on the strength of the other. "[unk]" is included in the phrase list as a mandatory third element: without it the decoder has no legal path for out-of-grammar audio and must force-fit every cough and audience question onto the nearest command — typically "next slide" — which is threat TM-002/019 firing through its own front-line defense.

UNKNOWN-TOKEN POLICY (a design decision to confirm at the gate): finalizedPhrase strips at most ONE leading and ONE trailing "[unk]" token, rejects any interior "[unk]", and rejects a run of two or more at either end. Rationale: one leading unknown is the natural discourse marker ("okay next slide" — "okay" is out of vocabulary and decodes to a single [unk]), and rejecting it would recreate the UAT-2 BUG-11/12 class of dead command. Two or more, or an interior gap, means a SENTENCE was heard, not a command, and reassembling across it is exactly the audience-false-trigger threat. This is deliberately the same shape as matchCommand's audited leading/trailing filler strip, and both the policy and its cap are pure, configurable, and unit-tested.

LOGGING: nothing in src/voice/ ever logs the result JSON, the extracted text, a partial, or an audio buffer — at any level, in any build, including test output. ma_result_description() strings and the negotiated internal format (rate/channels/format) ARE safe to log once at startup and are the only diagnostics. miniaudio is compiled with MA_NO_DECODING/MA_NO_ENCODING/MA_NO_WAV/MA_NO_FLAC/MA_NO_MP3 so the file-write paths are PHYSICALLY ABSENT from the binary — the engine cannot persist audio even by mistake.

## 2. Pure (unit-testable) seam

Everything below is in pptv_core, has zero dependency on libvosk / miniaudio / CoreAudio / a microphone / the 40MB model, and is covered by the proposed assertions. pptv_tests links pptv_core ONLY, so this is enforced by the build graph rather than by discipline.

1. GRAMMAR CONSTRUCTION — voice_grammar. commandGrammarPhrases() builds the closed phrase list from compile-time constants: the 11 fixed command phrases matchCommand accepts, plus "go to slide <words(N)>" for N in 1..kGrammarMaxEnumeratedSlide, plus "[unk]". slideNumberWords(int) renders a number as spoken words. grammarVocabulary() flattens to a sorted unique token list for the pre-flight. buildGrammarJson() emits the exact NUL-terminatable UTF-8 JSON array. Takes NO arguments — the grammar can never be derived from deck content, filenames or slide counts.

2. GRAMMAR PAYLOAD VALIDATION — validateGrammarJson() -> GrammarDefect. Rejects non-JSON, non-array, empty array, non-string elements (each of which makes vosk_recognizer_new_grm dereference a null decode_fst_ and CRASH — verified: our model ships HCLr.fst+Gr.fst and no HCLG.fst, so the null branch is the live branch), and also rejects uppercase tokens, punctuation, double/edge spaces and a missing "[unk]" (each of which makes Vosk's literal space-tokenizer silently DROP a word with only a KALDI_WARN, permanently disabling a command).

3. VOCABULARY PRE-FLIGHT — checkVocabulary(vocabulary, std::function<bool(QString)> inModel) -> {ok, missing}. The predicate is injected, so the LOGIC is unit-testable with a fake; only the predicate's body (vosk_model_find_word) is I/O.

4. RESULT PARSING AND THE FINALS-ONLY RULE — voice_result. parseVoskResult() classifies by KEY ("text" => Final, "partial" => Partial, neither => Malformed, empty text => Empty) using QJsonDocument. finalizedPhrase() is the whole contract-#1 pipeline: Final only, [unk] policy, trim, non-empty. This is where a partial is guaranteed never to become a phrase.

5. UNKNOWN-TOKEN POLICY — UnknownPolicy{rejectInterior, maxEdgeUnknowns}. Pure, configurable, tested. Encodes the audience-false-trigger trade-off explicitly rather than burying it in the worker loop.

6. AUDIO FORMAT AND CHUNK ARITHMETIC — audio_format. isVoskCompatible() (asserted against the NEGOTIATED device format, not the requested one), samplesToBytes()/bytesToSamples() (naming away the accept_waveform-bytes vs accept_waveform_s-samples 2x trap), chunkSamples(16000,200)=3200, peakAmplitude() with INT16_MIN saturation.

7. SILENCE / STARVATION DETECTION — silence_watchdog. Clock-injected, so the decision logic for "the device says it is running but every buffer is zeros" and "callbacks have stopped arriving" is tested with synthetic timestamps and synthetic peaks.

8. DECODE ERROR BUDGET — consecutive accept_waveform -1 accounting with reset-on-success and an exhaustion threshold.

9. ENGINE STATE MACHINE — voice_state. nextState(), isListening() (true for exactly one state), voiceStateMessage() (non-empty and actionable for every failure state). The entire degrade-safely requirement is a pure function table.

10. MODEL PATH RESOLUTION AND LAYOUT AUDIT — model_path. Precedence (env override > bundle-relative > build-tree fallback) and the am/final.mdl sentinel, plus the layout audit that rejects an HCLG-based model. Filesystem access is behind an injected ModelProbe, so tests use a fake or a QTemporaryDir.

11. THREAD MARSHALLING — phrase_pump. Qt-only, no audio, no model; testable headlessly against the QGuiApplication that tests/test_main.cpp already constructs.

## 3. I/O seam (behind IRecognizer, UAT-validated)

Everything below is in pptv_voice, is NEVER linked by pptv_tests, and is validated by UAT with a real microphone and the real model via tools/voice_probe.cpp — not by unit tests.

BEHIND IRecognizer (src/command/recognizer_controller.hpp), implemented by class VoskRecognizer:
- Vosk C API handle lifecycle: vosk_set_log_level(-1), vosk_model_new / vosk_model_free, vosk_recognizer_new_grm / vosk_recognizer_free, vosk_recognizer_accept_waveform_s, vosk_recognizer_result, vosk_recognizer_reset, at most one vosk_recognizer_final_result at shutdown (discarded). Handles held in unique_ptr with custom deleters. NEVER called: vosk_recognizer_partial_result (contract #1 by construction) and vosk_recognizer_set_grm (not exported by the vendored macOS binary — I confirmed with nm -g that only _vosk_recognizer_new_grm is present; using it would link on Ubuntu CI and fail on the showtime Mac).
- vosk_model_find_word calls, used only as the body of the injected checkVocabulary predicate.
- The recognition worker thread itself: std::jthread creation/join, the timed wait, the ring drain loop, and the try/catch(...) wrappers around every non-exception-wrapped Vosk call.
- The 1 s silence warm-up feed.

BEHIND IAudioSource, implemented by class MiniaudioCapture:
- ma_context_init / ma_context_get_devices pre-flight enumeration (captureCount == 0 => no microphone, fail fast).
- ma_device_config_init / ma_device_init / ma_device_start / ma_device_stop / ma_device_uninit, and the notificationCallback (which does nothing but set an atomic — calling ma_device_* from it can deadlock on CoreAudio's device-tracking mutex).
- The real-time data callback and the ma_pcm_rb SPSC ring (acquire_write / commit_write / acquire_read / commit_read).
- Reading back the NEGOTIATED dev.sampleRate / dev.capture.format / dev.capture.channels and the internal* diagnostics, and asserting the backend is not ma_backend_null.

BEHIND MicPermission:
- macOS: AVCaptureDevice authorizationStatusForMediaType:AVMediaTypeAudio and requestAccessForMediaType: (mic_permission_mac.mm). In the GUI app, Qt's QMicrophonePermission is tried first; the .mm shim is both the fallback for QTBUG-144272 and the only path for the headless probe.
- Non-Apple: a stub returning Granted.

PACKAGING / PLATFORM I/O (not code, but only ever exercised outside unit tests):
- The staged-copy install_name_tool -id @rpath/libvosk.dylib + codesign re-sign, the .app Frameworks/ and Resources/ POST_BUILD copies, and the model zip SHA-256 verify + extract.

UAT COVERAGE FOR ALL OF THE ABOVE (tests/uat/sessions/<date>/, driven by voice_probe and the built .app): each of the five commands recognized from a real voice at a realistic distance; one spoken command moves exactly ONE slide (contract #1 end-to-end); audience-style speech and a cough during Paused move nothing (TM-002/019); the app launched from its FINAL absolute path on the showtime machine, on battery, Bluetooth off, projector attached, prompts for the microphone and then recognizes a real command; permission denied shows the blocking instruction screen and never claims to listen; unplugging the input device mid-session trips the watchdog banner within ~2 s; a >10 minute run survives Vosk's periodic decoder rebuild; no heard text appears in any log, terminal, or stderr.

## 5. CI plan

GOAL: CI stays green, fast, and microphone-free, and never spends the metered git-LFS quota on the 40 MB model. GitHub-hosted Ubuntu runners have no input device, so nothing in ctest may open one — which is already guaranteed by the link graph rather than by policy.

1. LFS, MADE EXPLICIT. actions/checkout currently has no lfs: key, so it defaults to false and sets GIT_LFS_SKIP_SMUDGE=1 — all three LFS-tracked paths land as ~130-byte pointer files. Harmless today, an opaque link failure the moment pptv_voice exists. Add lfs: false with a comment explaining it is deliberate, then a single new step that pulls exactly ONE object: git lfs install --local --skip-smudge; git lfs pull --include="third_party/vosk/lib/linux-x86_64/libvosk.so" --exclude="". The --exclude="" is required, not decorative: git lfs pull merges the flags with any configured lfs.fetchinclude/fetchexclude, and omitting it is the classic way this recipe silently pulls all 76 MB. Verify with file ... | grep -q 'ELF 64-bit' and sha256sum -c against 0f6e82ed2757ca422975d22f811dd79b577932a97711eafa1d6e89d79d46d4a4 from PROVENANCE.md, so a pointer file fails as one clear line instead of a cryptic link error. git-lfs is preinstalled on ubuntu-latest; no apt change needed.

2. CACHE THE OBJECT. actions/cache on .git/lfs/objects keyed by the library's own SHA-256 (immutable — a Vosk bump changes the key and misses exactly once). Repeat runs then cost zero LFS bandwidth. Pin the action by commit SHA to match the repo's existing style.

3. A BANDWIDTH REGRESSION GUARD, because a policy nobody can verify is a policy nobody keeps. One step asserting that third_party/vosk/model/vosk-model-small-en-us-0.15.zip and third_party/vosk/lib/macos-universal2/libvosk.dyld are STILL pointer files (head -c 128 | grep git-lfs.github.com/spec). If someone later drops lfs: true in, this fails loudly with an explanation instead of quietly burning 66 MB per push.

4. CONFIGURE WITHOUT THE MODEL: add -DPPTV_BUNDLE_VOSK_MODEL=OFF to the CMake configure step so the extraction target is not in the CI build graph and the 40 MB zip is genuinely never needed. Safe for coverage precisely because all model and microphone I/O is behind IRecognizer. CMake must also degrade gracefully on its own: a pointer-sized model zip is a STATUS message and a model-less configure, while a pointer-sized platform library actually being linked is a FATAL_ERROR naming the exact git lfs pull command.

5. TESTS LINK LINE IS THE SECURITY BOUNDARY. tests/CMakeLists.txt keeps target_link_libraries(pptv_tests PRIVATE pptv_core doctest::doctest) — never pptv_voice, never Vosk::vosk — with a comment stating that this is a deliberate security property. That single line is what makes 'unit-testable without a microphone or the model' mechanical rather than aspirational.

6. TWO NEW GREP GUARDS (cheap, high value, catch showtime-only failures at PR time):
   a) 'vosk_recognizer_partial_result' must not appear anywhere under src/. Not calling it at all is what makes IRecognizer contract #1 structurally impossible to violate; a runtime filter could regress, a compile-time absence cannot.
   b) 'vosk_recognizer_set_grm' must not appear anywhere under src/. I confirmed with nm -g on the vendored binary that this symbol is NOT exported by libvosk.dyld (only _vosk_recognizer_new_grm is) while the Linux .so DOES export it — so any use would build green on Ubuntu CI and fail to link on the Apple-Silicon showtime machine. This guard is the only thing standing between that mismatch and the stage.

7. CLANG-TIDY TRAP, FIXED BY FILE PLACEMENT. The lint glob is git ls-files '*.cpp' '*.cc' '*.cxx' ':(exclude)third_party/**' with --warnings-as-errors='*'. Putting the miniaudio implementation TU at third_party/miniaudio/miniaudio_impl.cpp means BOTH the clang-format and clang-tidy globs already exclude it — zero config change in ci.yml and scripts/run-tests.sh. (Putting it in src/voice/ would make clang-tidy compile the whole 4 MB header on every run, and the step is currently dormant only because no .clang-tidy file exists yet — that will change.) The new .mm file is not matched by either glob.

APT DEPENDENCIES: NO CHANGE. miniaudio section 2.3 states the Linux build needs only -ldl -lpthread -lm and no development packages (ALSA and PulseAudio are dlopen'd at runtime), and libvosk.so's DT_NEEDED list is only libstdc++/libm/libgcc_s/libc, all present on ubuntu-latest. .github/ci-deps-apt.txt stays exactly as it is.

## 6. Proposed test assertions (25) — NOT yet approved at a test gate


**grammar builder — closure and agreement with matchCommand**

- For every phrase p in commandGrammarPhrases() other than "[unk]", matchCommand(p).has_value() is true; and "[unk]" appears in commandGrammarPhrases() exactly once.
  - *why:* Two live-talk failures in one check. If the grammar contains a phrase the matcher rejects, the presenter says a phrase the engine is tuned to hear and NOTHING HAPPENS on stage. And without "[unk]" the decoder has no legal path for out-of-grammar audio, so every cough and audience question is force-fitted onto the nearest command — typically "next slide" — which is threat TM-002/019 firing through its own front-line defense.
- For every N in 1..kGrammarMaxEnumeratedSlide: parseSlideNumber(slideNumberWords(N)) == N, and matchCommand("go to slide " + slideNumberWords(N)) == Command{GoToSlide, N}.
  - *why:* A round-trip property that mechanically proves the grammar's spelling of numbers and F4's parser agree. Without it, "go to slide seventeen" can be perfectly decodable by Vosk yet unmappable by matchCommand — a jump command that silently does nothing, which on stage looks like the app ignoring the presenter.
- grammarVocabulary() equals exactly the expected closed set: the 10 command words {next, slide, previous, pause, presentation, the, continue, resume, go, to} + the number words required for 1..kGrammarMaxEnumeratedSlide + "[unk]"; and it contains none of {"stop","exit","quit","close","end","delete","open"}.
  - *why:* Every word in the vocabulary is a path by which audience speech can reach a command (TM-002/019). Set equality — not a subset check — is what makes the vocabulary provably CLOSED, and the denylist half guarantees no destructive-sounding word can ever be recognized at all.

**grammar payload — crash and silent-drop guards**

- buildGrammarJson() takes no arguments, returns a byte-identical result on repeated calls, and validateGrammarJson(buildGrammarJson()) == GrammarDefect::None.
  - *why:* The grammar MUST be a compile-time constant. A grammar derived from deck content, a filename, or a slide count read at runtime is both a crash vector and a silent-constraint-loss vector. The no-arguments signature plus determinism is the checkable form of that rule, and the self-validation proves our own payload passes the guard we ship.
- validateGrammarJson returns EmptyArray for "[]", NotArray for "{\"phrases\":[]}", NotJson for the truncated "[\"next slide\"", and NonStringElement for "[1,2]".
  - *why:* Each of these four inputs makes Vosk's UpdateGrammarFst take its early return, leaving decode_fst_ null; the very next line of the constructor dereferences it. Our model has HCLr.fst+Gr.fst and NO HCLG.fst (I verified the zip contents), so the null branch is the live branch — this is a HARD SEGFAULT ON STAGE, not a NULL return, and vosk_api.cc's try/catch(...) does not catch it.
- validateGrammarJson rejects ["Next Slide."] (uppercase and punctuation), ["next  slide"] (double space), and [" next slide"] (leading space), each with the corresponding GrammarDefect.
  - *why:* Vosk tokenizes each phrase with a literal getline(ss, token, ' '). "Slide." and the empty token produced by a double space are not vocabulary words, so they are DROPPED with only a KALDI_WARN and the phrase quietly becomes a shorter phrase. The command then never fires and there is no error, no return code, and no log anyone reads.
- checkVocabulary(grammarVocabulary(), probe) returns ok==true with an empty missing list when the injected probe knows every word; and returns ok==false with missing == {"resume"} when the probe reports only "resume" unknown.
  - *why:* This is the ONLY detector for Vosk silently dropping a grammar token at recognizer construction. A dropped "resume" is precisely the UAT-2 BUG-11 SEV-1 again: the presenter enters Paused for audience Q&A and cannot get out, mid-talk, with no error anywhere. The injected probe is what lets this logic be proven with no model loaded.

**result parser — finals vs partials (IRecognizer contract #1)**

- parseVoskResult classifies a payload carrying the "text" key as ResultKind::Final and one carrying the "partial" key as ResultKind::Partial — never the reverse — and a payload with neither key as Malformed; and finalizedPhrase(R"({"partial" : "next"})") == nullopt.
  - *why:* Contract item #1 from the F2/F3 audit. A partial forwarded to onPhrase means one spoken "next slide" dispatches on "next" and again on "next slide" — the deck jumps multiple slides per command (audit S7). Classifying by KEY rather than by heuristic is what makes the rule deterministic.
- finalizedPhrase applied to Vosk's actual pretty-printed output "{\n  \"text\" : \"next slide\"\n}" returns "next slide", identical to the compact form {"text":"next slide"}.
  - *why:* Vosk dumps results through SimpleJSON, which emits newlines, two-space indent, and a space on BOTH sides of the colon — while its EMPTY results are hard-coded compact strings. A hand-rolled substring parser would therefore pass every test written against compact literals and fail on every real utterance in production. This assertion forces a real JSON parse.
- finalizedPhrase returns nullopt and does not throw for: {"text" : ""}; the truncated "{\"text\":"; a 1 MB string of non-JSON junk; and {"alternatives":[{"text":"next slide","confidence":-812.4}]}.
  - *why:* An endpoint on pure noise legitimately yields empty text, and Kaldi endpointing fires on ~0.5 s of trailing silence, so this path runs constantly during a talk. Malformed input must fail safe, and nothing here may throw — an exception escaping the worker thread function is std::terminate mid-talk. The alternatives shape is a defensive check that a result format we never enable cannot be mistaken for a phrase.

**unknown-token policy ([unk])**

- finalizedPhrase(R"({"text" : "[unk]"})") == nullopt.
  - *why:* With "[unk]" in the grammar (which is mandatory), out-of-grammar audio — a cough, a door, an audience question during Q&A — legitimately decodes to exactly this. The literal token must never reach RecognizerController::onPhrase; rejecting it here rather than relying solely on matchCommand returning nullopt keeps a bracketed token out of the dispatch path entirely.
- With the default UnknownPolicy, finalizedPhrase(R"({"text" : "[unk] next slide"})") == "next slide" and finalizedPhrase(R"({"text" : "next slide [unk]"})") == "next slide".
  - *why:* A single leading or trailing discourse marker is the normal way people speak — "okay next slide", "next slide please". Those filler words are OUT of our closed vocabulary, so Vosk renders them as one [unk]. Rejecting the whole utterance would make "okay next slide" a dead command, recreating exactly the UAT-2 BUG-11/12 class of failure the matcher's own edge-filler strip was added to fix. NOTE FOR THE GATE: this is the one deliberate loosening in the design and is the assertion to argue about.
- finalizedPhrase(R"({"text" : "next [unk] slide"})") == nullopt and finalizedPhrase(R"({"text" : "[unk] [unk] next slide"})") == nullopt.
  - *why:* The counterweight to the previous assertion, and the one that keeps TM-002/019 closed. An INTERIOR unknown means words were heard between "next" and "slide" — reassembling across that gap would manufacture a command nobody spoke. A RUN of unknowns at the edge means a sentence was heard, not a command: "...and that brings us to what I'd call the next slide in our thinking" must move nothing.

**thread marshalling (IRecognizer contract #2)**

- 50 distinct phrases delivered from a non-main QThread via PhrasePump::deliver() all invoke the handler on qApp->thread(), exactly once each, in the original order, after the main-thread event loop is spun.
  - *why:* Contract item #2 from the F2/F3 audit. RecognizerController::state_ is non-atomic, so a direct call from the recognition worker is a data race (audit S6) — and this is a race that would surface as a corrupted Active/Paused state under exactly the conditions of a live talk. Duplicates or reordering would move the deck to the wrong slide. Runs headlessly because tests/test_main.cpp already builds a QGuiApplication on the offscreen platform.
- Phrases delivered before PhrasePump::setEnabled(false) but not yet dispatched, plus any delivered after it, never reach the handler once the event loop is spun.
  - *why:* stop() must not emit a trailing command. vosk_recognizer_final_result flushes whatever partial utterance was in flight and the queue may already hold a phrase; if either fires after the presenter has stopped listening, the deck moves with nobody asking it to. The gate has to drop ALREADY-QUEUED items, not just future ones — which is why the assertion names both.
- A phrase handler that throws std::runtime_error does not propagate out of PhrasePump's queued invocation; the pump remains usable and a subsequent phrase is still delivered.
  - *why:* Same class as audit finding S3, one layer out. An exception escaping a Qt slot or the worker thread function is std::terminate — the app disappears mid-presentation. The 'remains usable' half matters too: one bad phrase must not silently kill voice control for the rest of the talk.

**audio format and chunk arithmetic**

- samplesToBytes(3200) == 6400, bytesToSamples(6400) == 3200, and chunkSamples(16000, 200) == 3200.
  - *why:* vosk_recognizer_accept_waveform takes a BYTE count and vosk_recognizer_accept_waveform_s takes a SAMPLE count — under the identical parameter name 'length'. Passing bytes to the _s variant reads 2x past the end of the buffer and feeds garbage; passing samples to the char* variant feeds half the audio. Both fail with no error and no log — every command simply stops working. Naming and testing the conversion is the cheapest possible guard against the single easiest bug in this API.
- isVoskCompatible returns true for {16000 Hz, 1 channel, s16} and false for each of {48000, 1, s16}, {16000, 2, s16}, and {16000, 1, f32}.
  - *why:* This predicate is applied to what CoreAudio ACTUALLY negotiated, not what we requested — miniaudio and CoreAudio do not always give you what you asked for. A rate mismatch silently destroys accuracy (the model is trained at 16k); interleaved stereo fed as mono decodes as garbage at double rate; and f32 handed to accept_waveform_f is copied UNSCALED into a pipeline expecting +/-32768 amplitudes, making the audio ~32768x too quiet so the recognizer hears silence. All three return success from every API.
- peakAmplitude returns 0 for an all-zero buffer, 1234 for a buffer whose largest magnitude is -1234, and 32767 (not a negative value, and no signed-overflow) for a buffer containing INT16_MIN.
  - *why:* This feeds the silence watchdog that is our only detector for denied microphone permission. If it mis-reports, a denied app looks healthy. The INT16_MIN case is separate because negating it is signed-overflow UB — the sanitizer build would trip on it, and an optimizer is entitled to do anything with it.

**model path and layout**

- resolveModelPath prefers a non-empty environment override even when the bundle path also exists; falls back to the bundle path when the override is empty; and returns ok==false for a directory that exists but contains no am/final.mdl, rather than returning that path.
  - *why:* The showtime machine IS the dev machine, so a build-tree fallback would let a completely broken .app (model never copied into Contents/Resources) pass every rehearsal and fail the instant the bundle is moved or build/ is cleaned. Bundle-first makes a packaging bug fail in rehearsal. The am/final.mdl sentinel means a HALF-copied model falls through instead of reaching vosk_model_new, which would return NULL and complain only to stderr.
- inspectModelLayout returns Ok for a directory containing am/final.mdl + conf/model.conf + graph/HCLr.fst + graph/Gr.fst; Incomplete when conf/model.conf is absent; and NotGrammarCapable when graph/HCLG.fst is ALSO present.
  - *why:* The NotGrammarCapable case is the quietest security failure in the whole feature. If the app is ever pointed at a model shipping HCLG.fst, vosk_recognizer_new_grm takes its else-branch, logs one stderr warning nobody reads, and builds a fully working recognizer over the FULL ~200k-word vocabulary. Grammar constraint gone, no crash, no error return — TM-002/019 silently re-enabled. I verified our pinned model has HCLr.fst + Gr.fst and no HCLG.fst; this assertion is what keeps it that way.

**degrade-safe state machine and watchdogs**

- isListening(s) is true for exactly one VoiceState (Listening) and false for each of Idle, PermissionRequired, PermissionDenied, ModelMissing, Loading, Muted, DeviceLost, Failed and Stopped; and voiceStateMessage(s) is non-empty for every one of those non-Listening states.
  - *why:* This is the codified form of 'never silently pretend to listen'. The UI derives the listening glyph from this single predicate, so a state that fails to listen but reports true is not representable. The message half guarantees every failure carries actionable text on the projector rather than a silent, healthy-looking app that ignores the presenter.
- nextState(Listening, AudioSilent) == Muted; nextState(Listening, AudioStopped) == DeviceLost; nextState(PermissionDenied, Start) == PermissionDenied; and for every VoiceState s, nextState(s, Stop) == Stopped.
  - *why:* Each transition covers a failure that fires NO notification on our platforms. CoreAudio deliberately swallows the stop event for a vanished default input device (there is a standing TODO in miniaudio saying so); ALSA/Pulse only post 'stopped' when stopping SUCCEEDS, which it does not on unplug. macOS prompts for the microphone exactly once ever, so a denial is permanent and unpromptable — Start must not pretend otherwise. And Stop must be total, so no path can leave the engine half-running.
- SilenceWatchdog: chunks with peak 0 arriving every 20 ms for 5000 ms yield Verdict::Silent; no chunk at all for 2000 ms yields Verdict::NoAudio; and a single subsequent chunk with peak 4000 returns the verdict to Healthy.
  - *why:* Denied macOS microphone permission, a hardware mute switch, a muted input in Sound settings, and miniaudio's silent fallback to the null backend are ALL indistinguishable from 'the room is quiet' — ma_device_init and ma_device_start both return MA_SUCCESS, the callback fires on schedule, and every buffer is zeros. Core Audio hands a denied app zeros and reports success. This watchdog is the only thing that can tell the difference, so its logic must be proven with synthetic timestamps rather than discovered on stage.
- DecodeErrorBudget(limit=5): four consecutive onError() calls leave exhausted()==false; the fifth makes it true; and an onSuccess() after three errors resets consecutive() to 0 so a later run of four does not exhaust it.
  - *why:* A -1 from accept_waveform_s is a swallowed internal exception leaving the recognizer in an indeterminate state. One is survivable via vosk_recognizer_reset(); a sustained run means the recognizer is wedged, and the app must switch to a visible 'voice control degraded — use the clicker' state instead of continuing to look like it is listening. Reset-on-success is what stops an occasional glitch over a 45-minute talk from accumulating into a false alarm.

## 7. Open risks (from the design)

- SILENT ZEROS IS THE HEADLINE RISK AND NO UNIT TEST CAN CATCH IT. If NSMicrophoneUsageDescription is missing or the plist is not wired via MACOSX_BUNDLE_INFO_PLIST at CONFIGURE time, Qt never links libqdarwinmicrophonepermission.a, so TCC is never asked, so nothing crashes — and miniaudio then opens the AUHAL input unit successfully and delivers zeros forever. Every API returns success. On stage this looks like a working app that ignores the presenter. Mitigations in this design: the .mm AVCaptureDevice pre-flight, the SilenceWatchdog, and a post-build assertion that PlistBuddy can read the key out of the built bundle. The only real proof is a live recognition in pre-flight — 'no errors in the log' is not evidence.
- TCC GRANT IS LOST ON EVERY REBUILD. The bundle is ad-hoc/linker-signed with no stable designated requirement, so macOS cannot tell that version N+1 is the same app as version N. Every ninja that relinks the executable changes the cdhash. Best case a fresh prompt; worst case System Settings still shows the toggle ON while the new binary silently gets zeros. The app must be frozen days before the talk and a real recognition re-verified after ANY rebuild. Moving the .app after granting also invalidates it — copy to the final absolute path FIRST, grant SECOND, never move again.
- THE macOS PATH IS NOT IN CI AT ALL. ci.yml is ubuntu-only, so the install_name_tool -id @rpath/libvosk.dylib + ad-hoc re-sign, the .app Frameworks/ and Resources/ copies, the plist key, and the OBJCXX permission shim are exercised ONLY by scripts/run-tests.sh on the dev workstation — and macOS is the showtime platform. I confirmed the concrete trap: LC_ID_DYLIB on the vendored binary is the bare name 'libvosk.dylib', so an -rpath entry alone can never resolve it (dyld consults LC_RPATH only for @rpath/-prefixed load paths). Recommend at minimum a local post-build check on otool -l output; a macos-latest CI leg is the real fix if there is time.
- THE [unk] EDGE-STRIP POLICY IS A JUDGEMENT CALL AND THE MOST LIKELY THING TO NEED RETUNING AT UAT. maxEdgeUnknowns=1 is a guess at how Vosk renders a single out-of-vocabulary discourse marker; the mapping from spoken filler to emitted [unk] tokens is not 1:1 and is not knowable without real audio. Set it to 0 (reject any [unk]) if UAT shows any false trigger — a dead 'okay next slide' is recoverable by repeating the phrase, a false slide jump in front of an audience is not.
- VOSK GRAMMAR MODE IS A BIGRAM LM, NOT AN EXACT PHRASE MATCHER (ngram_order=2, discount=0.5). It can legitimately emit cross-phrase sequences such as 'next presentation'. This is expected and fine — matchCommand's closed phrase-level grammar is the actual guarantee — but it must not be used to argue that the matcher can be relaxed to fuzzy or substring matching because 'Vosk already constrains it'. Both layers are load-bearing.
- kGrammarMaxEnumeratedSlide IS SET BEFORE THE DECK IS KNOWN. 'go to slide N' is only enumerated up to that compile-time bound; beyond it the presenter must use next/previous. It cannot be derived from the loaded deck, because a runtime-built grammar is both a segfault vector and a constraint-loss vector. Karl should set the constant once he knows the final slide count — this is a decision for the gate.
- MODEL LOAD IS 0.5-3 SECONDS OF BLOCKING I/O (~62 MB across final.mdl, HCLr.fst, Gr.fst) plus a LanguageModelEstimator pass for the grammar. It is off the GUI thread by design, but it must complete well before the presenter walks on, and the Loading state must be visible. Separately, Vosk rebuilds its decoder and feature pipeline roughly every 10 minutes of continuous audio to bound memory — a talk longer than ten minutes will hit at least one rebuild stall at an utterance boundary. Budget for it; do not mistake it for a hang.
- DEFAULT INPUT DEVICE CAN SWITCH MID-TALK. AirPods connecting, or a USB-C dock or HDMI audio device appearing, silently re-points the macOS default input. miniaudio auto-recovers for the default device on CoreAudio but explicitly does NOT on ALSA/Pulse, and even on CoreAudio the stop event is swallowed when it cannot switch. Consider pinning the built-in microphone by CoreAudio device UID rather than passing NULL, and turn Bluetooth off on the showtime machine. Also quit every conferencing app — one holding the input makes the orange indicator lie about who owns the mic.
- THE SHIPPED BINARY RECORDS AN ABSOLUTE PATH TO libvosk.so ON LINUX. The .so carries no DT_SONAME (readelf -d), so IMPORTED_NO_SONAME makes CMake link it by full path. That is green in CI and on a dev box but not relocatable — a Linux AppImage would need patchelf --set-soname plus --replace-needed. Linux packaging is already P2 per Bible section 11, so record it as a known limitation rather than solving it now.
- DEFERRED UAT-2 ITEMS (directional aliases, spoken-number naturalness, out-of-range slide numbers pending F7) are flagged in WALK-STATE as landing with this feature, but they are matchCommand/F4 concerns rather than engine concerns. Folding them in here would change an audited, frozen grammar at the same time as introducing the audio stack. Recommend they stay a separate change so a UAT regression can be attributed to one of the two.

## 8. Adversarial review findings (ALL must be addressed before implementation)

### Lens: live-talk

**Verdict:** NEEDS_CHANGES — the Vosk/miniaudio API layer is the best-researched part of this design and I found no factual errors in it, but the live-talk risk calculus is inverted in two places (the [unk] edge-strip defaults permissive, and Muted/DeviceLost are terminal in violation of FRD §2-E3's required 5 s auto-retry), the "go to slide N" grammar can jump to the WRONG slide for N above kGrammarMaxEnumeratedSlide with no defense at any layer, and every failure path terminates in a keyboard fallback (F6) that does not exist and is scheduled after this feature.

- **[Critical]** THE DEGRADE PATH IS VAPOR. Every failure mode in this design terminates in 'voice degraded — use the clicker' (Failed state, DecodeErrorBudget exhaustion, PermissionDenied, ModelMissing, DeviceLost). WALK-STATE.md §5 shows F6 keyboard parity is scheduled AFTER this feature, and after F5 overlay too; grep of src/ finds zero keyPressEvent/QShortcut/Key_Right. src/main.cpp constructs StartView and shows it — there is no presentation mode, no slide advance, no fullscreen. FAILURE SEQUENCE: mic permission is silently stale after a rebuild (the design's own openRisk #2), engine reports Failed, projector shows 'use the clicker', Karl presses Right Arrow — nothing is bound. - **[Critical]** THE [unk] EDGE-STRIP DEFAULT IS BACKWARDS FOR THIS RISK PROFILE, AND THE 20-SECOND FORCED ENDPOINT MAKES IT THE HIGHEST-VOLUME CODE PATH IN THE TALK. Verified from the model: conf/model.conf sets frame-subsampling-factor=3 and rule2.min-trailing-silence=0.5; Kaldi's rule5 forces an endpoint at ~20 s of continuous audio. The design's sole defense is 'interior [unk] rejects it, and a RUN of 2+ edge [unk]s rejects it'. That assumes Vosk renders a long out-of-grammar stretch as MULTIPLE [unk] tokens. The design's own openRisk admits 'the mapping from spoken filler to emitted [unk] tokens is not 1:1 and is not knowable without real audio' — but never connects that admission to the 130-endpoint case. A bigram LM with a self-loop on [unk] and discount=0.5 has every incentive to collapse a long unknown stretch into ONE token. If it does, '...which brings me to the next slide' emits '[unk] the next slide' or '[unk] next slide' -> one leading [unk] stripped -> NEXT SLIDE FIRES while Karl is mid-sentence. The design then compounds it by DEFAULTING to the permissive setting (maxEdgeUnknowns=1) and saying 'set it to 0 if UAT shows any false trigger'. - **[High]** THE SILENCE WATCHDOG WILL FALSE-POSITIVE ON A PRESENTER WHO PAUSES, AND ITS FALSE POSITIVE IS UNRECOVERABLE. The only proposed assertion is 'chunks with peak 0 arriving every 20 ms for 5000 ms yield Verdict::Silent'. Peak EXACTLY zero is the denied-TCC/null-backend signature; a real microphone in a quiet auditorium has a noise floor of roughly ±2 to ±20 LSB and NEVER returns bit-exact zero. But nothing in the design says the threshold is bit-exact zero rather than 'below some epsilon', and the assertion set does not pin it. FAILURE SEQUENCE: Karl pauses for effect / drinks water / listens to a question his lapel mic barely picks up. If the implementation uses any nonzero epsilon, 5 seconds of that trips Verdict::Silent -> AudioSilent -> state Muted -> isListening() false -> the glyph drops and a 'microphone appears muted' banner appears on the projector while the mic is perfectly healthy. Then, per the terminal-state finding above, there is no Muted->Listening transition asserted, so voice is dead for the remaining 40 minutes. Five seconds is also far too short a window for a talk — pauses of 5-15 s are completely normal. Separately, the watchdog is a 1 Hz QTimer on the GUI thread: if the GUI thread blocks for >2 s (deck load, a big QImage render, the pre-render cache work Bible §3 wants off-thread but F7 has not built yet), poll() is called late and the naive now-lastCallbackMs comparison self-trips NoAudio.
  - *fix:* Split the verdict into two clocks with different confidence, and make only the high-confidence one touch isListening(). (a) HARD/never-alive: bit-exact zero across EVERY sample AND no nonzero sample has EVER been seen since ma_device_start — this is denied TCC / hardware mute / null backend, fire at ~3 s, drive the visible state. (b) SOFT/went-quiet: was healthy, now below threshold — fire at >=30 s, show an advisory only, never drop isListening(). Require bit-exact zero for the hard case, not an epsilon. Add lateness tolerance to the pure logic: poll(nowMs) must ignore an interval where (nowMs - lastPollMs) exceeds the expected period by more than ~2x, because that gap is the watchdog's own scheduling delay, not the microphone's.
- **[High]** THE 1.3 SECOND RECOGNITION BUDGET IS UNBUDGETED AND THE DESIGN SPENDS 200 ms OF IT FOR NO BENEFIT. FRD §2.2 (frd.md:54) is explicit: slide change visible <=1.5 s p95 from end of utterance, decomposed as 'recognition <=1.3 s + render/display <200 ms'. The design contains no latency budget, no assertion, and no measurement plan. Adding up the fixed costs from the verified config: conf/model.conf rule2.min-trailing-silence=0.5 means Kaldi will not endpoint until 500 ms AFTER Karl stops speaking (unavoidable, baked into the pinned model); + up to 200 ms of chunk quantization because the design drains in chunkSamples(16000,200)=3200-sample units, so the chunk containing the endpoint boundary arrives up to a full chunk late; + up to 60 ms of miniaudio backend buffering (periodSizeInMilliseconds=20 x MA_DEFAULT_PERIODS=3); + the 10 ms worker poll; + lattice finalization and JSON construction, which the research notes spikes to tens of ms; + the queued-connection hop, up to one GUI event-loop turn. Typical ~0.85 s, but with any decode spike, a CPU-contended render, or the ~10-minute CleanUp() rebuild landing on that utterance, it exceeds 1.3 s. Karl perceives the app as unresponsive and repeats — which is the double-advance path from the previous finding.
  - *fix:* Halve the avoidable quantization: use chunkSamples(16000, 100) = 1600 samples. Vosk internally slices at sample_frequency*0.2 anyway, upstream's own C example feeds 1600 samples, and the per-call overhead difference is negligible — 200 ms buys nothing and costs 15% of the recognition budget. Encode the budget as a pure, asserted constant: kEndpointSilenceMs(500) + kChunkMs + kWorkerPollMs + kDeviceBufferMs <= 1300, so a future chunk-size change fails a test instead of failing on stage. Then MEASURE it in UAT: timestamp at pump delivery, timestamp at command dispatch, and record end-of-utterance-to-visible with a stopwatch over >=20 utterances to get a real p95.

  - [unk] RUN SATURATION: finalizedPhrase("[unk] next slide") == nullopt under the default policy, and for N = 1..10 leading [unk] tokens the result is nullopt at EVERY N — so the guarantee does not depend on how many tokens Vosk chooses to emit for one unknown stretch.
  - STATE-MACHINE RECOVERY: nextState(Muted, AudioHealthy) == Listening; nextState(DeviceLost, DeviceRecovered) is Listening or Loading; nextState(Failed, Retry) != Failed. Plus a total invariant: for every VoiceState except Stopped, some event leads out of it — no absorbing failure state.
  - RETRY CADENCE (FRD §2-E3): a pure RetryPolicy asserting a capture re-attempt is due every 5000 ms while in DeviceLost/Muted, that a successful retry clears the banner, and that retry never triggers a model reload (kModelReloadOnRetry == false).
  - WATCHDOG ZERO-DISCRIMINATION: chunks with peak == 1 (a real noise floor) arriving for 60000 ms must yield Healthy, NOT Silent. Only bit-exact peak == 0 may yield the hard verdict. This is the assertion that stops a quiet room from being reported as a dead microphone.
  - WATCHDOG TWO-CLOCK SPLIT: assert a distinct hard verdict (no nonzero sample EVER observed since start, fires at ~3000 ms, may drive isListening false) versus a soft verdict (was healthy, now quiet, requires >= 30000 ms, must NOT drive isListening false).
  - WATCHDOG SELF-LATENESS: poll(nowMs) where nowMs jumps 5000 ms in a single step while chunks were being recorded throughout must NOT report NoAudio — the gap is the GUI thread's scheduling delay, not the microphone's.
  - OVERRUN BUDGET: an OverrunBudget/AudioHealth pure type — dropped frames exceeding ~1% of expected frames over a 10 s window trips exhausted(); a clean window resets it; and nextState(Listening, AudioOverrun) reaches a visibly degraded state.
  - GO-TO-SLIDE RANGE GUARD: for N > kGrammarMaxEnumeratedSlide, "go to slide " + slideNumberWords(N) is NOT in commandGrammarPhrases(); and a pure slideJumpSupported(deckSlideCount) returns false when deckSlideCount > kGrammarMaxEnumeratedSlide, so the app can refuse jumps instead of jumping wrong.
  - LATENCY BUDGET AS CODE: kEndpointSilenceMs(500) + kChunkMs + kWorkerPollMs + kDeviceBufferMs <= 1300 (FRD §2.2 recognition budget), and chunkSamples(16000, kChunkMs) with kChunkMs <= 100 — so a future chunk-size increase fails a test rather than the talk.
  - EXACTLY-ONE-OUTCOME PER PHRASE: end-to-end across pump + controller, one finalized phrase produces EXACTLY ONE of {a dispatched Command, an unmatched-phrase signal} — never both, never neither. The proposed assertions test the pump hop in isolation and never test the composed pipeline.
  - UNMATCHED-PHRASE CHANNEL (FRD §2-E2): the unmatched handler fires exactly once for a finalized phrase matchCommand rejects, exactly once for a navigation phrase dropped because the controller is Paused, and never for a phrase that dispatched a command.
  - PAUSED RESUME SPECIFICITY: while Paused, a bare "continue" and a bare "resume" do NOT resume, while "continue presentation"/"resume presentation"/"continue the presentation"/"resume the presentation" do. If the gate rejects this tightening, an explicit test must document that bare single words DO resume, so the accepted risk is recorded rather than accidental.
  - INDICATOR TOTALITY: the UI indicator predicate is total and injective over {VoiceState} x {RecognizerController::Active, Paused} — no two distinct conditions render identically, so "paused" can never look like "armed and listening".
  - SHUTDOWN IDEMPOTENCE: stop() called twice is a no-op on the second call and does not re-enter join; and after stop(), a phrase already queued in the pump plus one delivered afterwards both fail to reach the handler (the proposed setEnabled(false) assertion covers the pump but not stop() as a whole).
  - WARM-UP DRAIN: the warm-up feed exercises the same r==1/0/-1 branch as steady state, and after warm-up the recognizer state is clean (assert via a following synthetic feed producing a fresh, non-concatenated result).

### Lens: security-privacy

**Verdict:** NEEDS_CHANGES — the design is unusually strong on the C-API ownership rules, the finals-only contract and the degrade-safe surface, but its central security claim ("matchCommand's closed phrase-level grammar is the HARD guarantee") does not survive contact with the actual matchCommand: it accepts bare single-word "resume"/"continue"/"pause", which a bigram LM structurally cannot prevent the decoder emitting, giving audience speech a one-word exit from the Paused state that exists to protect against exactly that (TM-002/019); the maxEdgeUnknowns=1 policy compounds it by accepting "[unk] <command> [unk]" on an unbounded amount of absorbed speech; there is no output-side vocabulary closure check; the model is loaded from an env-overridable, integrity-unverified, signature-unsealed path; the ring drain never states it honours acquire_read's short return; ma_device_stop's failure (which is the norm on unplug) is unchecked before teardown; and voice_probe prints heard text into a git-tracked UAT tree, violating the binding Bible section 8 contract.

- **[Critical]** SINGLE-WORD COMMANDS RE-ARM NAVIGATION DURING Q&A — the exact window TM-002/019 exists to protect. The design's central security argument is "Vosk's bigram grammar is a soft constraint; the HARD guarantee is matchCommand's closed phrase-level grammar." I read matchCommand: it accepts core == "pause", core == "continue", and core == "resume" as bare single words (src/command/command_matcher.cpp, the PausePresentation and ContinuePresentation branches). A bigram LM structurally CANNOT enforce phrase length — removing bare "resume" from commandGrammarPhrases() does not stop the decoder emitting a lone "resume", because the unigram survives from "resume presentation". So the hard layer is a 1-word match and the soft layer cannot help. Failure sequence: presenter says "pause presentation" -> RecognizerController::Paused -> audience Q&A begins (by design, the noisiest period of the talk) -> any audience utterance whose tail acoustically resembles "resume"/"continue" force-decodes to that word (it is one of only ~10 legal non-[unk] words) -> finalizedPhrase passes it -> matchCommand returns ContinuePresentation -> controller returns to Active -> the NEXT audience sentence containing "next slide" moves the deck. Paused is the ONLY audience-protection mechanism in the product and its exit is a single word.
  - *fix:* Split the phrase grammar the recognizer is allowed to produce from the phrase grammar matchCommand accepts. Introduce a recognizer-facing minimum-length rule: phrases arriving via IRecognizer must be >=2 tokens. Concretely, add `bool isRecognizerAdmissible(const QString&)` in voice_result (pure, in pptv_core) that rejects any single-token phrase, and apply it inside finalizedPhrase BEFORE delivery; keep bare "pause"/"resume"/"continue" working for the keyboard path (F6), which is not audience-reachable. Then drop the single-word entries from commandGrammarPhrases() as well, so the LM is not biased toward them. This costs the presenter nothing ("pause presentation" / "resume presentation" both still work and are the phrases the Manifesto Q1 grammar actually specifies) and closes the pivot in the kill chain.
- **[High]** THE [unk] EDGE-STRIP POLICY IS UNSOUND BECAUSE ONE [unk] TOKEN DOES NOT MEAN ONE SPOKEN WORD. maxEdgeUnknowns=1 accepts "[unk] next slide", "next slide [unk]" AND "[unk] next slide [unk]" (one leading + one trailing are both within cap). The design's own openRisks admits "the mapping from spoken filler to emitted [unk] tokens is not 1:1 and is not knowable without real audio" — Kaldi's unknown-word model can absorb an arbitrarily long stretch of out-of-grammar audio into a single [unk] arc. So "...and I think the point we should really make before we move to the next slide is that..." can legitimately endpoint as "[unk] next slide [unk]" and the design ACCEPTS it. Compounding: the design justifies this as "deliberately the same shape as matchCommand's audited leading/trailing filler strip." That justification is false. matchCommand's strip removes a FIXED, ENUMERATED, AUDITED set of 17 leading and 12 trailing words (okay, um, please, ...), none of which are in the closed Vosk vocabulary — so matchCommand's strip is inert on recognizer output. The [unk] strip removes an UNBOUNDED, UNKNOWABLE amount of speech. It is a brand-new, unaudited loosening wearing an audited one's clothes.
  - *fix:* Set the shipped default to maxEdgeUnknowns = 0 (reject any phrase containing [unk] anywhere) and make the >0 value reachable only from a test/debug constructor, never from the shipped VoskRecognizer. The design's own risk register already reaches this conclusion ("a dead 'okay next slide' is recoverable by repeating the phrase, a false slide jump in front of an audience is not") — make 0 the default rather than the fallback. If UAT proves the dead-command rate is unacceptable, the correct remedy is adding the discourse markers to the grammar vocabulary as EXPLICIT words so matchCommand's audited, enumerated strip handles them — not widening an unbounded wildcard.
- **[High]** NO OUTPUT-SIDE CLOSURE CHECK: the design validates the grammar going IN to Vosk but never validates the phrase coming OUT. Two concrete leaks follow. (a) Vosk grammar mode is a bigram LM and the design correctly notes it can emit cross-phrase sequences like "next presentation" — those are simply handed to matchCommand and relied upon to return nullopt. (b) More seriously, matchCommand's GoToSlide branch is NOT an exact phrase match: it requires the prefix "go to slide " and then delegates to parseSlideNumber, whose isFiller() list silently DROPS the tokens {go, to, slide, number, the, please, hey, jump, show, me, and, page}. Since "the", "go", "to", "slide" are all IN the closed Vosk vocabulary, a bigram emission of "go to slide five slide" or "go to slide five the" parses to GoToSlide(5). So matchCommand accepts an unbounded family for GoToSlide (prefix + up to 12 number/filler tokens), which contradicts the design's repeated claim that matchCommand is "the closed phrase-level grammar" and "the HARD guarantee." The hard layer is looser than the security argument assumes.
  - *fix:* Add a pure allowlist gate as the LAST step of finalizedPhrase, in pptv_core: after [unk] handling and trimming, require that the residual phrase is byte-identical to a member of commandGrammarPhrases(). Anything else -> nullopt, never delivered. This is O(1) against a ~30-element set, makes the closure property provable rather than argued, structurally neutralizes the bigram LM's cross-phrase emissions, and makes the pump physically incapable of delivering a string that is not one of the enumerated commands. It also means an unexpected model token (<unk>, [noise], !SIL, <eps>, </s> — emitted by other Kaldi models) can never reach the dispatch path, rather than relying on a literal "[unk]" string filter.
- **[High]** THE MODEL IS AN UNTRUSTED, UNVERIFIED, ENV-OVERRIDABLE BINARY DESERIALIZATION SURFACE AT LOAD TIME. Three compounding gaps: (1) resolveModelPath gives the environment variable HIGHEST precedence ("env override > bundle-relative > build-tree"), so any value in a shell profile, a launchd plist, or a hostile process's environment points vosk_model_new at an arbitrary directory. Kaldi then deserializes am/final.mdl, graph/HCLr.fst and graph/Gr.fst — ~62 MB of raw binary parsed by C++ with no bounds hardening. There is no path canonicalization and no traversal rejection, though the Bible mandates exactly that for the .pptx (TM-015). (2) SHA-256 verification happens ONCE, against the ZIP, at first extraction. Both proposed CMake variants (the configure-time `elseif(NOT EXISTS ...)` form in wiring, and the stamp form in packaging — which contradict each other and must be reconciled) skip verification entirely on every subsequent build. The EXTRACTED tree is never verified, at build or at load. (3) The showtime bundle is adhoc/linker-signed with `Sealed Resources=none` (confirmed in the design's own research), so Contents/Resources/vosk-model-.../ is NOT covered by the code signature — the model is writable and swappable with zero detectable change to the app. inspectModelLayout is a filename-shape check, not an integrity check: it detects only the one documented bypass (HCLG.fst present) and cannot detect a substituted final.mdl or HCLr.fst.
  - *fix:* (a) Demote the environment override BELOW the bundle path, and compile it out of the GUI target entirely — expose PPTV_VOSK_MODEL_DIR only in voice_probe / test builds via a preprocessor guard, exactly as the packaging section already does for PPTV_VOSK_MODEL_DIR. (b) Record per-file SHA-256 for am/final.mdl, conf/model.conf, graph/HCLr.fst and graph/Gr.fst in third_party/PROVENANCE.md, emit them as compile-time constants, and verify them in the worker thread immediately BEFORE vosk_model_new — failure -> VoiceState::ModelMissing (rename to ModelUnavailable to cover both cases). Hashing 62 MB is ~0.2 s on the showtime Mac and it runs concurrently with the Loading state you already show. (c) Canonicalize the resolved path and reject any component that escapes the bundle when the override is not in use. (d) Record in the security audit that unsealed bundle resources are an accepted residual risk (consistent with TM-022/023) only once (a)-(c) are in place.
- **[High]** BUFFER SIZING AT THE accept_waveform_s BOUNDARY IS UNSPECIFIED FOR THE SHORT/WRAPPED READ. The design says the worker "drains the ring in chunkSamples(16000,200) = 3200-sample units, and calls vosk_recognizer_accept_waveform_s(rec, samples, sampleCount)". ma_pcm_rb_acquire_read hands back a pointer INTO the ring plus the number of frames actually available, and it CLAMPS at the buffer wrap — exactly as the design's own research states for acquire_write ("acquire_write clamps at the buffer wrap, so loop twice at most"). Nothing in the design, the pureSeam, or the 24 proposed assertions states that the sample count passed to Vosk must be the count acquire_read RETURNED rather than the 3200 that was requested. If the fixed 3200 is passed at a wrap boundary, accept_waveform_s reads up to 3200 shorts (6400 bytes) past the end of the ring allocation. This is the single most likely genuine memory-safety defect in the feature, it is in the hot loop so it fires within seconds, and it is silent under a Release build (ASan would catch it, but nothing in ctest exercises this path because pptv_tests deliberately cannot link pptv_voice — the very isolation that makes the design safe elsewhere leaves this code untested by construction).
  - *fix:* Make the invariant a pure, testable function rather than a comment. Add `int drainableSamples(int requested, int available)` (or have chunkSamples take an `available` argument) in audio_format.hpp returning min(requested, available), assert it in test_audio_format.cpp including available==0 and available<requested, and require the worker to call accept_waveform_s ONLY with that return value. Additionally, since the ring is a wrapping buffer, either loop the acquire/commit pair until drained, or copy into a stack-local std::array<int16_t,3200> and feed that — the copy costs 6.4 KB memcpy per 200 ms and removes the aliasing question entirely. Add `-DPPTV_VOICE_ASAN` UAT step running voice_probe under the existing build-asan/ tree for >=60 s of live audio, since ctest structurally cannot cover this.
- **[High]** SHUTDOWN'S UAF GUARANTEE DEPENDS ON ma_device_stop() SUCCEEDING, AND ON UNPLUG IT DOES NOT. The design states "ma_device_stop() first, from the GUI thread — its return is the ONLY guarantee no callback is in flight", then proceeds unconditionally to disable the pump, join the worker, free the recognizer, uninit the device and uninit the ring. Its own research establishes that on ALSA/Pulse the stopped notification is suppressed precisely because "stopping failed ... due to the device being physically unplugged", and on CoreAudio a vanished default input has the stop event deliberately swallowed. So on the exact failure the design spends most of its watchdog budget detecting (DeviceLost), ma_device_stop() returns non-MA_SUCCESS, the synchronization point does not hold, and the code then calls ma_pcm_rb_uninit() and destroys MiniaudioCapture while a CoreAudio render callback may still be executing memcpy into the ring and storing to the peak/timestamp atomics. That is a use-after-free on a real-time thread, at the exact moment the presenter is unplugging a dock mid-talk. The return value of ma_device_stop is never mentioned, never branched on, and no assertion covers it.
  - *fix:* Branch on the ma_result. On MA_SUCCESS, proceed with the documented teardown. On anything else, do NOT uninit the ring or destroy the capture object on that path: set the pump disabled, transition to DeviceLost, and leak-with-intent — leave the ma_device and ma_pcm_rb allocated for the remaining process lifetime (a 64 KB ring and one ma_device is a rounding error next to a crash on stage), or retry ma_device_stop once after a bounded wait and only then uninit. Add an explicit design statement: 'ma_device_uninit is reached ONLY on a successful stop.' Also log ma_result_description() for the failure — that string is device metadata, never audio, so it is Bible section 8-safe.
- **[High]** voice_probe PRINTS HEARD TEXT AND UAT OUTPUT IS COMMITTED TO GIT. tools/voice_probe.cpp is specified to 'print each FINALIZED phrase and the Command it maps to'. That is verbatim Confidential audio content (Bible section 5.1.1) rendered to stdout. It is also the designated UAT driver, and I confirmed `tests/uat/sessions/` is git-tracked (git ls-files returns 10 files across two session dirs) with no .gitignore rule covering it — .gitignore only excludes *.log, render-out/ and render-out-png/. The established UAT workflow is to paste tool output into a session markdown file and commit it. So the shortest path from a rehearsal of a Confidential executive talk into permanent, distributable git history is: run voice_probe, copy terminal output, paste into tests/uat/sessions/<date>/, commit, push. Bible section 8 permits heard text ONLY in an opt-in, local, user-deletable rehearsal log (settings.json rehearsal_log_enabled, default false) — not in a dev tool's default output and certainly not in version control. The design also contradicts itself here: its UAT acceptance list includes 'no heard text appears in any log, terminal, or stderr' while the same document specifies a tool whose purpose is to print heard text to a terminal.
  - *fix:* Default voice_probe to printing ONLY the matched CommandType (or '(no command)') plus the utterance's token count and the current VoiceState — never the phrase text. Gate the text output behind an explicit `--echo-heard-text` flag that prints a one-line warning to stderr ('Confidential audio content will be printed; do not paste this output into any file') and is documented as rehearsal-only. Add `tests/uat/**/*probe*.txt`, `*.transcript`, `*.wav` to .gitignore, and add a line to the UAT session template forbidding verbatim transcripts in submissions. Reword the design's own UAT acceptance criterion so it is achievable.
- **[High]** NON-LISTENING STATES DO NOT STOP THE CAPTURE DEVICE — the app can claim it is not listening while the microphone is live. isListening() is true for exactly one state, and the UI glyph is derived from it alone; the design calls this 'never silently pretend to listen'. But the inverse is unhandled and is the worse failure for a Confidential-audio app. VoiceState::Failed is entered when DecodeErrorBudget is exhausted, and the design's action is to show 'voice degraded, use the clicker' — it never says the device is stopped. Same for Muted (the device MUST still be running, since that is how the SilenceWatchdog observes zero peaks) and for DeviceLost. Result: the glyph says NOT LISTENING, isListening() returns false, the presenter reasonably concludes the mic is off and speaks freely about whatever follows the talk — while ma_device is started, the RT callback is memcpy'ing live executive audio into the ring at 16 kHz, and macOS's orange microphone indicator is lit. That is a Confidential-data containment failure and it directly contradicts the guarantee the state machine is sold on. There is no assertion anywhere binding capture-device state to isListening().
  - *fix:* Make the binding mechanical and pure. Add `bool shouldCaptureBeRunning(VoiceState)` to voice_state.hpp, define it as exactly `isListening(s) || s == VoiceState::Muted` (Muted is the one legitimate exception, and only because detection requires audio), and have VoskRecognizer drive ma_device_start/ma_device_stop from that predicate on every state transition — never from ad-hoc call sites. Assert `shouldCaptureBeRunning(s) == false` for Idle, PermissionRequired, PermissionDenied, ModelMissing, Loading, DeviceLost, Failed and Stopped. For the Muted exception, the voiceStateMessage must explicitly say the microphone is still open (e.g. 'Microphone is open but receiving silence — check the mute switch'), so the presenter is never told 'not listening' while it is.
- **[Medium]** THE LINUX BUILD CAN STREAM CONFIDENTIAL AUDIO OFF THE MACHINE, BREAKING THE OFFLINE INVARIANT. On non-Apple targets the design deliberately keeps miniaudio's runtime linking (MA_NO_RUNTIME_LINKING is applied only under if(APPLE)) and passes NULL for the backend list, so ma_context_init walks the default priority order and will select PulseAudio when present. PulseAudio is network-transparent by design: `PULSE_SERVER=tcp:host:4713` in the environment redirects the capture stream to a remote sink, and the app has no visibility into it — ma_device_init and ma_device_start both return MA_SUCCESS, the SilenceWatchdog sees healthy non-zero peaks (the remote server can echo audio back), and nothing in the design would notice. Bible section 10 lists 'no network calls of any kind (offline invariant — a CI grep guard is a candidate)' in the never-do list, and this feature adds the two largest third-party binaries in the project (a 26 MB libvosk.so and a 4 MB miniaudio header that dlopen()s system audio libraries) without ever exercising that named guard. The proposed CI plan adds two greps (partial_result, set_grm) and no offline check. macOS is showtime so this is not a stage risk, but Linux is a supported target per Bible section 15 and is the platform CI and any Linux rehearsal run on.
  - *fix:* (a) On non-Apple, call ma_device_init_ex with an explicit backend array of {ma_backend_alsa} only, dropping PulseAudio from the candidate list — ALSA has no network transport. If Pulse must be kept for device compatibility, unset PULSE_SERVER/PULSE_SINK/PULSE_SOURCE/PULSE_COOKIE before ma_context_init and assert the negotiated backend. (b) Add the offline-invariant CI guard the Bible already names: `nm -D --undefined-only third_party/vosk/lib/linux-x86_64/libvosk.so | grep -E 'socket|connect|getaddrinfo|gethostby|SSL_|curl_' ` must be empty, and the same check against the linked pptv_voice objects. That converts a documented invariant into an enforced one at the moment the project first acquires binaries that could violate it.
- **[Medium]** validateGrammarJson HAS NO EMBEDDED-NUL DEFECT, AND THE GRAMMAR CROSSES A C STRING BOUNDARY. buildGrammarJson() returns a QByteArray and the design passes g.constData() to vosk_recognizer_new_grm, which takes `const char*` and parses to the first NUL. QByteArray can legally contain an interior '\0' and its size() would not reflect the truncation. The enumerated GrammarDefect set covers NotJson, NotArray, EmptyArray, NonStringElement, uppercase, punctuation, double space and edge space — but not an embedded NUL. Failure sequence: a NUL introduced anywhere in the payload (a bad slideNumberWords implementation, a QString/QByteArray conversion bug, a future refactor that builds the array via QJsonDocument::toJson on data containing one) truncates the C string. Best case the grammar silently becomes a shorter phrase list and a command is permanently dead with no signal; worst case the truncation lands mid-array, json::JSON::Load returns a non-array, UpdateGrammarFst takes its early return, decode_fst_ stays null and the constructor dereferences it — the hard segfault-on-stage path the design correctly identifies but has not fully closed. Related and smaller: validateGrammarJson must be shown to operate on the same bytes that are passed to Vosk (i.e. validate the NUL-terminated prefix, not the QByteArray's full length), or the guard can pass while Vosk sees something different.
  - *fix:* Add GrammarDefect::EmbeddedNul and reject any payload where `qstrlen(g.constData()) != static_cast<size_t>(g.size())`. Assert it directly in test_voice_grammar.cpp with a literal QByteArray containing '\0'. Also state explicitly in the header contract that validateGrammarJson's guarantee is about the NUL-terminated C string Vosk will see, and mark buildGrammarJson's return as guaranteed NUL-free (it is built from compile-time constants, so this is trivially true today — the point is to keep it true).
- **[Medium]** vosk_set_log_level(-1) LEAVES KALDI WARNINGS ON FOR THE ENTIRE TALK, AND SimpleJSON BYPASSES THE LOG HANDLER ENTIRELY. Kaldi's filter is `if (env.severity > GetVerboseLevel()) return;` with kWarning == -1, so level -1 suppresses kInfo (including the KALDI_LOG that dumps the whole grammar JSON) but still prints every KALDI_WARN to stderr for the whole session — including the lattice warnings that fire during decoding, i.e. during the talk. Separately, SimpleJSON's parser writes its own errors directly to std::cerr, which no Vosk log level can suppress. The design treats -1 as settled ('a Bible section 8 control, not cosmetics') and chose it to keep the missing-vocabulary warning visible — but the design ALSO adds checkVocabulary()/vosk_model_find_word as the authoritative pre-flight for exactly that condition, so the warning has no remaining job. On the showtime machine the app may be launched from a Terminal window that is mirrored to the projector, or stderr may be captured by a wrapper script; anything Kaldi prints then lands in front of the audience.
  - *fix:* Set vosk_set_log_level(-2) in Release builds (suppressing kWarning too) and keep -1 only under a debug/dev flag, since checkVocabulary already covers the one warning that mattered. Additionally, in the GUI target redirect stderr to /dev/null (or to a Bible-compliant sink) for the lifetime of the recognizer, so the SimpleJSON std::cerr path and any future unguarded Kaldi print have nowhere to go. Add a UAT step that runs the built .app with stderr captured to a file and asserts the file contains no token from the command vocabulary.
- **[Medium]** THE PermissionDenied AND ModelMissing LATCHES ARE LAUNDERABLE THROUGH Stop. The design asserts both `nextState(PermissionDenied, Start) == PermissionDenied` (correct — macOS prompts once ever, so the denial is permanent) and `for every VoiceState s, nextState(s, Stop) == Stopped` (total, so nothing is left half-running). Those two are individually sound and jointly unsound: the sequence Start -> PermissionDenied -> Stop -> Stopped -> Start reaches whatever nextState(Stopped, Start) yields, which must be Loading or Listening for the engine to be restartable at all. The permanent denial has been forgotten by a two-event path, and the engine then proceeds to open a device that TCC will feed all zeros — landing the app in exactly the 'looks like it is working, ignores the presenter' state the whole degrade-safe surface exists to prevent. Same laundering applies to ModelMissing. No assertion covers any multi-event path; every proposed state assertion is a single transition.
  - *fix:* Assert the reachability property, not just individual edges: for every event sequence of length <= 4 drawn from the full VoiceEvent set, starting at PermissionDenied or ModelMissing, VoiceState::Listening is never reached. That is a small exhaustive search and is exactly the kind of property a pure state table makes cheap to prove. Implement it by making Start from Stopped re-enter PermissionRequired (forcing a fresh permission check) rather than jumping to Loading, and by having the model layout/integrity check re-run on every entry to Loading.
- **[Medium]** MA_NO_NULL IS MISSING FROM THE ACTUAL BUILD WIRING, AND THE miniaudio IMPL TU HAS TWO CONFLICTING HOMES. The design's headline availability risk is miniaudio's silent fallback to ma_backend_null: ma_device_init and ma_device_start both return MA_SUCCESS, the callback fires on schedule, and every buffer is zeros forever. Its stated mitigation is 'MA_NO_NULL and an assert that the negotiated backend is not ma_backend_null'. But the concrete target_compile_definitions block in the wiring section lists MA_NO_DECODING MA_NO_ENCODING MA_NO_WAV MA_NO_FLAC MA_NO_MP3 MA_NO_ENGINE MA_NO_RESOURCE_MANAGER MA_NO_NODE_GRAPH MA_NO_GENERATION — and NOT MA_NO_NULL. The mitigation exists in prose and in the files table but not in the build. Compounding this, the design specifies the implementation TU at two different paths in the same document (third_party/miniaudio/miniaudio_impl.cpp in the files list, src/voice/miniaudio_impl.cpp in the wiring snippet and filesToAdd), with different define strategies for each — one puts the MA_NO_* defines in the TU source, the other on the CMake target. If the file lands at the third_party path while the defines live on the pptv_voice target, it still works; but any later refactor that moves the TU out of that target silently re-enables the file-write paths (MA_NO_ENCODING/MA_NO_WAV), which is the mechanism the design relies on to make audio persistence 'PHYSICALLY ABSENT from the binary'.
  - *fix:* Put every MA_NO_* define in the implementation TU itself, immediately above #include "miniaudio.h", including MA_NO_NULL — a #define in the one TU that expands the header cannot be lost by a target refactor and cannot be silently dropped from a CMake edit. Keep the target-level defines too if desired (they are harmless duplicates). Resolve the TU to a single path: third_party/miniaudio/miniaudio_impl.cpp, which the design correctly notes is already excluded from both the clang-format and clang-tidy globs with zero config change. Add a CI grep asserting MA_NO_ENCODING, MA_NO_WAV and MA_NO_NULL appear in that file — the physical-absence claim is a security control and should be enforced like one.
- **[Medium]** THE CI GREP GUARDS ARE SCOPED TO src/ ONLY, AND THERE IS NO SECTION-8 GUARD AT ALL. The design leans hard on two greps ('vosk_recognizer_partial_result must not appear anywhere under src/', 'vosk_recognizer_set_grm must not appear anywhere under src/') and calls the first one what makes contract #1 'structurally impossible to violate rather than filtered at runtime'. But tools/voice_probe.cpp is not under src/, and it is precisely the file where a developer debugging live recognition would add partial-result printing — it is the only executable that touches a real mic, its whole purpose is diagnosing why a phrase was not recognized, and partial results are the obvious diagnostic. The set_grm guard has the same hole and the same consequence (links green on Ubuntu CI, fails to link on the Apple-Silicon showtime machine). - **[Medium]** THE CLOSED VOCABULARY IS WIDER THAN IT NEEDS TO BE, WHICH DIRECTLY AMPLIFIES TM-002/019. Two avoidable widenings: (1) 'the' is in the vocabulary solely to support 'pause the presentation' and 'continue the presentation'. 'the' is the most frequent word in English; including it hands the bigram decoder a high-probability bridge through ordinary speech and materially raises the rate at which a sentence decodes into vocabulary words instead of unknowns. (2) kGrammarMaxEnumeratedSlide is explicitly 'SET BEFORE THE DECK IS KNOWN' and the design defers the value to the gate. ### Lens: testability

**Verdict:** NEEDS_CHANGES — the pure/IO seam is drawn one layer too shallow: the recognition loop (contract #1's "exactly once" half), the ring-drain/chunk arithmetic, and the nine-step startup gating are all real branching logic stranded on the untestable side of IRecognizer, and three of the design's safety guards are `assert()` calls that NDEBUG deletes from the Release binary this project actually ships.

- **[Critical]** IRecognizer contract #1 is TWO properties — (a) never consume interim results, (b) exactly ONE handler call per utterance — and only (a) has any enforcement. The design's mechanism for (a) is the CI grep proving vosk_recognizer_partial_result is never referenced. That grep says nothing about (b). The loop that turns decoder returns into handler calls (drain ring -> chunk -> accept_waveform_s -> branch on 1/0/-1 -> copy JSON -> finalizedPhrase -> pump_.deliver) lives entirely in vosk_recognizer.cpp, inside pptv_voice, which pptv_tests is forbidden to link. So it has ZERO automated coverage at any level. Concrete failure sequence that ships green: worker gets r==1, copies json, calls deliver(); an exception from a later Vosk call is caught by the try/catch(...) and the loop `continue`s without clearing the local `json`, or a refactor moves deliver() outside the `if (r==1)` block. Now every 200ms chunk re-delivers the last final phrase. One spoken "next slide" advances the deck 5 times. Every proposed unit test still passes, every CI grep still passes, and the only detector is UAT with a live mic. finalizedPhrase being pure does not help: it is a per-payload function with no memory of how many times it was called.
  - *fix:* Add a second I/O seam so the loop itself becomes pure-testable. Define `class IDecoder { virtual DecodeOutcome feed(std::span<const int16_t>) = 0; virtual void reset() = 0; virtual QByteArray finalResult() = 0; };` with `struct DecodeOutcome { enum Kind {NeedMore, Final, Error} kind; QByteArray json; }`, implemented by VoskDecoder in pptv_voice. Move the loop body into a `RecognitionLoop` class in pptv_core taking IAudioSource + IDecoder + PhrasePump + DecodeErrorBudget. Then tests drive a FakeDecoder that returns a scripted sequence of outcomes with no model and no mic, and (b) becomes checkable. pptv_voice shrinks to: miniaudio glue, the Vosk C-API adapter, and the permission shim — pure byte-moving, exactly what the design claims it already is.
- **[Critical]** Three of the design's safety-critical guards are specified as `assert()`, which is a no-op in this project's shipping binary. Verified: root CMakeLists.txt forces `set(CMAKE_BUILD_TYPE Release CACHE STRING "" FORCE)` when unset, and scripts/run-tests.sh configures `-DCMAKE_BUILD_TYPE=Release`. Release defines NDEBUG, so `assert` expands to nothing. The three guards are: (1) startup step 6, "assert validateGrammarJson(g) == GrammarDefect::None BEFORE the call" — this is the only thing standing between a malformed payload and a hard SEGFAULT inside vosk_recognizer_new_grm (the design's own research proves decode_fst_ stays null and is dereferenced, uncatchable); (2) miniaudio_capture.cpp "Asserts the NEGOTIATED format via isVoskCompatible()"; (3) "asserts the backend is not ma_backend_null". In the binary that actually goes on stage, all three evaluate to nothing. The pure functions validateGrammarJson / isVoskCompatible get 100% unit-test coverage while their CALL SITES are compiled out — the tests prove the guard works and the product never runs it.
  - *fix:* Ban `assert` from src/voice/ outright (add a CI grep alongside the partial_result/set_grm greps). Replace each with an unconditional check that returns a typed failure and drives the state machine: GrammarDefect != None -> VoiceState::Failed with a message and NO call to vosk_recognizer_new_grm; !isVoskCompatible(negotiated) -> VoiceState::Failed and no ma_device_start; backend == ma_backend_null -> VoiceState::Failed. Each must be reachable from a test via the startup-gate function in finding #3.
- **[Critical]** The startup sequence is pure ORCHESTRATION logic — a nine-step decision tree with five distinct abort branches — and it sits entirely on the untestable side. Every input to it is pure and unit-tested (MicPermissionStatus, ModelLocation, ModelLayout, VocabularyCheck, GrammarDefect), but the function that CONSUMES those five values and decides "open a device / do not open a device / which VoiceState to enter" is hand-written straight-line code in vosk_recognizer.cpp with no test. Nothing in the proposed assertion set would fail if an implementation computed inspectModelLayout(), ignored the return value, and called vosk_model_new anyway; or checked permission but started ma_device_start before the vocabulary pre-flight; or entered VoiceState::Listening after a Denied permission. The design's strongest safety claim — "Denied -> NO device is opened" — is a code-reading assertion, not a checkable one.
  - *fix:* Extract a pure total function into pptv_core: `std::variant<Proceed, VoiceState> startupGate(MicPermissionStatus, ModelLocation, ModelLayout, VocabularyCheck, GrammarDefect)`. VoskRecognizer::start() calls it once and is structurally incapable of touching a device or a model unless it returns Proceed. Then the exhaustive property is a unit test: over the full cross product of the five enums, Proceed is returned if and only if (Granted AND location.ok AND Layout::Ok AND vocab.ok AND GrammarDefect::None); every other combination returns a VoiceState for which isListening() is false and voiceStateMessage() is non-empty. That is ~200 cases from a nested loop, runs in microseconds, needs no mic and no model.
- **[High]** The SilenceWatchdog assertion tests a feeding pattern the real system will never produce, so it cannot detect the failure mode it exists for. The assertion says "chunks with peak 0 arriving every 20 ms for 5000 ms yield Verdict::Silent" — i.e. 250 onChunk() calls. But the architecture says the watchdog is driven by "a 1 Hz GUI-thread watchdog that reads ma_device_get_state() plus the two atomics and feeds SilenceWatchdog", and the RT callback "compute[s] peakAmplitude() over the chunk into a std::atomic<int>" — a plain store, not a max-accumulate. So in production the watchdog receives FIVE samples over 5000 ms, each being the peak of one arbitrary 20 ms slice sampled 1000 ms apart. Failure sequence: presenter pauses between sentences for 1.5 s (utterly normal); two consecutive 1 Hz polls land in that gap and read peak ~0; over a 45-minute talk, five consecutive polls landing in gaps is close to certain. Result: a "microphone appears muted" banner on the projector while the mic is fine. The inverse is worse — the atomic is last-write-wins, so a healthy mic that happens to be sampled during silence and a genuinely dead mic are literally the same observation, which is the exact discrimination the watchdog was built to make.
  - *fix:* Change the producer contract to a peak-since-last-read: the RT callback does a lock-free `atomic_fetch_max` (or CAS loop) into peakSinceRead_, and the 1 Hz poller does `exchange(0)` so it sees the max over the whole interval. Then restate the assertion at the real cadence, and add the false-alarm counterweight: SilenceWatchdog fed one sample per 1000 ms with peak 0 for 5 consecutive samples -> Silent; fed peak 0,0,0,0,900 -> Healthy (one live sample in five clears it); fed a quiet-but-live room (peak 300 every second for 60 s) -> Healthy, never Muted. Also pin the boundary: at exactly 5000 ms is it Silent or Healthy?
- **[High]** finalizedPhrase returns std::optional<QString>, so EIGHT semantically different rejection paths collapse into one indistinguishable value. Proposed assertions check `== nullopt` for: a partial payload, empty text, truncated JSON, 1 MB junk, the alternatives shape, bare "[unk]", interior "[unk]", and a run of two edge "[unk]". Every one of those tests passes against an implementation that does `if (!doc.isObject() || !obj.contains("text")) return nullopt;` and then `if (text.contains("[unk]")) return nullopt;` — i.e. an implementation with NO [unk] edge-strip policy at all, and no partial/final key discrimination. The suite would be fully green while the design's single most-argued decision (maxEdgeUnknowns=1) is entirely absent from the code. A test that cannot distinguish correct rejection from accidental rejection is not testing the property it names.
  - *fix:* Return a discriminated outcome: `struct PhraseOutcome { enum Reason {Accepted, NotFinal, EmptyText, Malformed, UnknownOnly, InteriorUnknown, TooManyEdgeUnknowns} reason; QString phrase; }`. Restate every nullopt assertion as an assertion on the REASON, not on emptiness. This also unblocks F5 TranscriptOverlay (PROJECT_BIBLE.md line 153 requires heard text + why-it-was-rejected in the opt-in overlay) without reopening this audited seam later, and without adding logging that Bible section 8 forbids.
- **[High]** Chunk accumulation and ring-drain arithmetic — genuinely error-prone pure integer logic — is stranded in vosk_recognizer.cpp with no test. The only proposed coverage is `chunkSamples(16000,200) == 3200`, which is a multiplication, not the algorithm. The actual algorithm must: aggregate 320-frame callbacks into 3200-sample feeds; handle ma_pcm_rb_acquire_read returning SHORT because of the buffer wrap (two segments per logical read) as distinct from short because the ring is nearly empty; carry a remainder across iterations; and decide what to do with a sub-chunk remainder at stop. Failure sequence: the implementation treats a wrap-induced short read as "ring empty", commits it, and sleeps 10 ms — the ring now permanently holds up to 3199 samples it never drains under steady load, the recognizer is fed a stream with a periodic gap, and every command decodes as noise. There is no unit test that can see this and the only symptom is "voice stopped working".
  - *fix:* Extract `class PcmChunker` into pptv_core: `void push(std::span<const int16_t>)`, emitting complete kChunkSamples-sized chunks through a callback, with `pending()` and an explicit `flush()` policy. The I/O shell becomes literally `acquire_read -> chunker.push(seg) -> commit_read`, twice for a wrap. Assert the concatenation property: pushing a buffer in any arbitrary segmentation yields byte-identical chunk output to pushing it contiguously — that single property test kills the entire wrap-handling bug class with no mic.
- **[High]** Binding contract #3 ("never log or persist heard text or deck content") has ZERO proposed assertions. It is enforced only by prose, by two CI greps that target unrelated symbols (partial_result, set_grm), and by MA_NO_ENCODING removing file writers. Nothing detects the realistic regression: a developer adds `qWarning() << "unmatched phrase:" << text;` while debugging a UAT bug, it survives review because it looks like diagnostics, and on stage a terminal or crash log carries verbatim audience speech. Note this is the one contract that also has a live conflict — Bible section 8 line 153 permits heard text in the opt-in TranscriptOverlay — so "nobody would do that" is not a safe assumption.
  - *fix:* Two additions, both cheap. (1) A runnable unit assertion: in test_voice_result.cpp install a qInstallMessageHandler that captures every Qt message, run the full pure pipeline over a corpus containing a distinctive sentinel ("zzqx sentinel phrase"), and CHECK that no captured message and no stdout/stderr byte contains the sentinel. (2) A third CI grep: qDebug|qInfo|qWarning|qCritical|std::cout|std::cerr|printf|fprintf must not appear anywhere under src/voice/, with a single narrowly-allowlisted startup diagnostics line.
- **[High]** No assertion couples phrase DELIVERY to VoiceState, so "voice degraded, use the clicker" and "voice still moves the deck" can be simultaneously true. The design gates the UI glyph on isListening() and gates the pump on setEnabled(), but never asserts the two agree. Failure sequence on stage: DecodeErrorBudget exhausts -> VoiceEvent::DecodeErrorBudgetExhausted -> VoiceState::Failed -> the projector shows "voice degraded, use the clicker" -> the presenter picks up the clicker -> but the worker thread is still running and the pump was never disabled, so a marginal recognition ALSO fires NextSlide -> the deck advances two slides. Same shape for Muted and DeviceLost. This is precisely the class of failure this project treats as SEV-1, and it is a two-line pure predicate away from being mechanically impossible.
  - *fix:* Add `bool deliversPhrases(VoiceState)` to voice_state.hpp and assert `deliversPhrases(s) == isListening(s)` for every state — one predicate, no drift possible. Then require by construction that PhrasePump::setEnabled is only ever called as `pump_.setEnabled(deliversPhrases(state_))` from the single place that commits a state transition, and add a CI grep that setEnabled( appears exactly once in src/voice/.
- **[High]** The state machine has no asserted RECOVERY path, which recreates UAT-2 BUG-11 (stuck-in-Paused, SEV-1) one layer down. The proposed transitions are all one-way into failure: Listening+AudioSilent -> Muted, Listening+AudioStopped -> DeviceLost, and Stop -> Stopped from everywhere. Meanwhile the SilenceWatchdog assertion explicitly promises "a single subsequent chunk with peak 4000 returns the verdict to Healthy" — so the watchdog recovers but there is no asserted transition that consumes that recovery. Failure sequence: presenter's mic is hardware-muted for 6 seconds while adjusting the lapel -> Muted -> presenter unmutes -> watchdog says Healthy -> no assertion, and quite possibly no code, moves Muted back to Listening -> voice control is dead for the remaining 40 minutes with the banner still up. Identically for DeviceLost after the device comes back (miniaudio DOES auto-recover the default device on CoreAudio and fires _rerouted).
  - *fix:* Assert the recovery half explicitly: nextState(Muted, AudioHealthy) == Listening; nextState(DeviceLost, DeviceRestored) == Listening; and state the deliberate exception — nextState(Failed, AudioHealthy) == Failed, because an exhausted decode budget must NOT self-clear. Add the global safety property in the same test: for every (s,e), if nextState(s,e) == Listening then e is one of an explicitly enumerated small set of recovery/ready events — so no stray watchdog event can ever light the listening glyph.
- **[High]** The design treats the [unk] edge-strip policy as load-bearing safety, but matchCommand ALREADY rejects every [unk]-bearing string — and that free backstop is untested, so it can be silently removed. I verified this empirically by linking the real libpptv_core.a: matchCommand returns nullopt for "[unk]", "[unk] next slide", "next slide [unk]", "next [unk] slide", "[unk] the next slide [unk]", "[unk] pause [unk]" and "go to slide [unk]". The mechanism is matchCommand's edge-punctuation strip (^[\s[:punct:]]+) turning "[unk]" into the token "unk]" or "unk", which is in no filler set and matches no command. That is a genuine second layer — but it is incidental, undocumented, and one regex tweak away from vanishing. Meanwhile the design's own risk register says the [unk] policy "is a guess" and "the most likely thing to need retuning at UAT". Retuning an untested guess that is believed to be the only defense is how a false trigger reaches the stage.
  - *fix:* Add the universal property as a test in test_command_matcher.cpp (not test_voice_result.cpp — it is a matcher property): for every phrase p in commandGrammarPhrases() and every insertion position, matchCommand(p with "[unk]" inserted) == nullopt, plus the bare "[unk]" case. - **[Medium]** The effective GoToSlide range exceeds kGrammarMaxEnumeratedSlide by an untested amount, and the design never characterizes it. Because Vosk grammar mode is a bigram LM (the design says so itself), any word sequence over the vocabulary is emittable, not just the enumerated phrases. I verified matchCommand("go to slide twenty one") returns a valid GoToSlide(21) — a phrase that would NEVER be in commandGrammarPhrases() if kGrammarMaxEnumeratedSlide is 20, yet is fully reachable because both "twenty" and "one" are in the vocabulary. So the real jump range is roughly 1..99 for any N >= 21, not 1..N. The proposed assertions only cover the enumerated range, so the actual reachable behavior — including whether any reachable pair produces a WRONG number rather than nullopt — is unasserted. Karl is being asked to set kGrammarMaxEnumeratedSlide at the gate under a false belief about what it bounds.
  - *fix:* Add a cross-product assertion over the emitted vocabulary rather than the enumerated phrases: for every ordered pair (a,b) of number words in grammarVocabulary(), matchCommand("go to slide " + a + " " + b) either returns nullopt or returns GoToSlide whose slideNumber == *parseSlideNumber(a + " " + b). Same for singletons and triples. That proves the bigram-reachable space is either rejected or arithmetically correct, and it documents the true range so the gate decision is informed.
- **[Medium]** Both PhrasePump concurrency assertions are non-deterministic as written; one can hang CI rather than fail it. (a) "50 distinct phrases delivered from a non-main QThread ... after the main-thread event loop is spun" specifies no synchronization point. A single processEvents() may drain 12 of 50 while the worker is still posting, so the test either flakes or is written as `while (count < 50) processEvents();` — which HANGS forever against the exact bug it is meant to catch (a pump that drops phrases). A hanging job on a 6-day timeline is strictly worse than a red one. (b) "Phrases delivered before setEnabled(false) but not yet dispatched" is not establishable from a worker thread at all: you cannot observe "posted but not yet dispatched" across a thread boundary without a race, so the test would be written with a sleep and would pass vacuously on a fast machine.
  - *fix:* (a) Restate with the synchronization made explicit: post all 50 from the worker, JOIN the worker (so all 50 are provably in the queue), then spin with a bounded deadline (QElapsedTimer, 5 s) and CHECK(!timedOut) before CHECK(received == 50) — a dropped phrase then FAILS in 5 s instead of hanging. (b) Restate as a same-thread test: deliver() uses Qt::QueuedConnection unconditionally, so calling it from the pump's own thread still queues; deliver 5 -> setEnabled(false) -> deliver 2 more -> processEvents -> CHECK(received == 0). That is fully deterministic and tests exactly the stated property.
- **[Medium]** The ring-buffer overrun path has a counter and nothing else — no policy, no state, no budget, no assertion — while an overrun is strictly more dangerous than the decode errors that DO get a budget. The design says: "bump an atomic overrun counter if acquire_write returns short (DROP, never block)". Dropping mid-utterance splices two discontinuous audio segments into one utterance the recognizer is still accumulating. Failure sequence: a slide-render hitch or the Vosk ~10-minute decoder rebuild stalls the worker for 300 ms; the ring drops 300 ms out of the middle of "next slide"; the spliced audio is fed as one continuous utterance and decodes to whatever the constrained bigram LM finds nearest — and because the grammar is closed and "[unk]" competes against only 11 short phrases, "nearest" is very often a real command. So an overrun does not degrade to silence, it degrades to a possible WRONG COMMAND. Nothing detects it, nothing resets the in-flight utterance, nothing surfaces it.
  - *fix:* Treat an overrun as an utterance-integrity event, not a statistic. Add to the pure layer: `enum class OverrunAction {Ignore, ResetUtterance, Degrade}` and `OverrunAction onOverrun(int droppedSamples)` on (or beside) DecodeErrorBudget, with unit assertions: a drop of any non-zero size during an in-flight utterance returns ResetUtterance (so the worker calls vosk_recognizer_reset and abandons the spliced audio rather than decoding it); N overruns within a window returns Degrade. Wire the worker to obey the return value.
- **[Medium]** The vocabulary set-equality assertion is brittle in a way that pushes it toward becoming tautological. As written it hardcodes "the 10 command words {next, slide, previous, pause, presentation, the, continue, resume, go, to} + the number words required for 1..kGrammarMaxEnumeratedSlide + [unk]" — but the number-word half cannot be hardcoded without re-deriving it, so the natural implementation is `expected = union of split(commandGrammarPhrases())`, which is exactly what grammarVocabulary() does. The test then proves nothing. And the denylist half ({stop, exit, quit, close, end, delete, open}) proves nothing about the words NOT on the list, which is the entire risk surface. Separately: the 10 command words are correct — I checked matchCommand and it accepts exactly 11 fixed phrases over exactly those 10 words — so the number is right, but the assertion shape is wrong.
  - *fix:* Replace with three non-tautological properties. (1) Derivation: grammarVocabulary() == sorted-unique split of commandGrammarPhrases() on ' ' — this is the consistency check, keep it, but do not call it closure. (2) Provenance: every phrase in commandGrammarPhrases() is either "[unk]" or satisfies matchCommand(p).has_value() — this is what actually makes the vocabulary a function of the AUDITED matcher grammar. (3) A hard size cap with a small literal bound: CHECK(grammarVocabulary().size() <= 40). The cap is what catches an accidental vocabulary explosion; the denylist can stay as a cheap extra but must not be presented as the closure guard.
- **[Medium]** The design's own file manifest is internally inconsistent, which will produce a half-wired test suite. The files[] array names src/voice/voice_grammar.*, voice_result.*, audio_format.*, voice_state.*, silence_watchdog.*, model_path.* and SIX test files (test_voice_grammar, test_voice_result, test_audio_format, test_voice_state, test_model_path, test_phrase_pump), and tests/CMakeLists.txt's stated role is "Six new test files appended". But wiring.filesToAdd names src/voice/vosk_grammar.*, vosk_result.* and only THREE test files (test_vosk_grammar, test_vosk_result, test_phrase_pump), and places miniaudio_impl.cpp at src/voice/ while the architecture section places it at third_party/miniaudio/ (the placement the whole clang-tidy/clang-format exclusion argument depends on). Since new tests are wired ONLY by being appended to the explicit list in tests/CMakeLists.txt, a stale list silently drops three test files — they compile nowhere, run nowhere, and ctest reports green.
  - *fix:* Reconcile to one manifest before implementation. Prefer files[] (voice_* naming, six test files, miniaudio_impl.cpp under third_party/). Then add a guard that makes the drop impossible: a CI step asserting that every tests/test_*.cpp on disk appears in tests/CMakeLists.txt — `comm -23 <(ls tests/test_*.cpp | xargs -n1 basename | sort) <(grep -o 'test_[a-z_]*\.cpp' tests/CMakeLists.txt | sort)` must be empty. Also drop src/voice/.clang-tidy from the manifest; it is contradicted by the third_party placement.
- **[Medium]** Model-path and layout coverage has holes exactly where the quiet failures are. (a) inspectModelLayout's NotGrammarCapable case is asserted only for "HCLG.fst is ALSO present" — the hybrid. The realistic bad input is a full-size model that ships HCLG.fst and NO HCLr/Gr, which under the proposed rules would classify as Incomplete (missing HCLr/Gr), producing a "model incomplete" message for what is actually the silent-grammar-loss scenario the design calls "the quietest security failure in the whole feature" — right diagnosis, wrong message, and someone will then "fix" the layout check by relaxing it. (b) There is no assertion for the directory not existing at all (ModelLayout::Missing is named in prose only). (c) resolveModelPath's behavior for a non-empty but INVALID env override is undefined. If it silently falls through to the bundle, a UAT operator who points PPTV_VOSK_MODEL_DIR at a typo'd path runs the bundled model while believing they are testing the override — every UAT result for that session is attributed to the wrong artifact.
  - *fix:* Add: inspectModelLayout(HCLG.fst present, HCLr/Gr absent) == NotGrammarCapable (classify HCLG presence BEFORE completeness, so the message names the real problem); inspectModelLayout(nonexistent dir) == Missing; and decide + assert resolveModelPath's invalid-override policy — recommend hard-fail with source == ModelPathSource::EnvOverride and ok == false, never a silent fallback, so a bad override is loud.
- **[Low]** Several assertions are stated in forms that are not checkable in doctest as written. (a) "buildGrammarJson() takes no arguments" is an API-shape property; the compiler enforces it, a test cannot. Only the byte-identical-on-repeat-call half is a runtime assertion. (b) "peakAmplitude returns 32767 ... and no signed-overflow for INT16_MIN" — the value is checkable, but "no signed-overflow" is only observable under UBSan; the repo has build-asan/ but nothing in the proposal requires the voice tests to be RUN there, so the UB half is asserted nowhere. (c) The 1 MB junk-string assertion pins no bound on runtime — a QJsonDocument parse of pathological input is fine, but the test should not silently become a multi-second test.
  - *fix:* (a) Keep determinism as the doctest assertion; enforce the signature with a static_assert(std::is_invocable_v<decltype(buildGrammarJson)>) in the test file, which does compile-time what prose cannot do at runtime. (b) Add an explicit requirement that scripts/run-tests.sh (or a CI leg) runs pptv_tests once under the existing build-asan configuration with -fsanitize=undefined, and note in the assertion that the INT16_MIN case is only meaningful there. (c) Bound it: CHECK the 1 MB case completes and add a doctest timeout or an elapsed-time CHECK under ~200 ms.
- **[Low]** Small arithmetic and lifetime edges with no assertions, each cheap to add and each capable of producing a silent total failure. (a) bytesToSamples(odd) is unspecified — an odd byte count truncates and misaligns every subsequent sample, converting the stream to noise with no error anywhere; this is the same class as the accept_waveform vs _s trap the design correctly fears. (b) chunkSamples(16000, 0) and chunkSamples(0, 200) return 0, and a worker that drains in 0-sample units spins forever. (c) peakAmplitude on an EMPTY span — frameCount can be 0 — is UB if implemented with *std::max_element. (d) Destroying a PhrasePump while phrases are still queued dereferences a dead object at the next event-loop spin; the repo already has build-asan/, so this is a runnable check that is simply absent.
  - *fix:* Add four assertions: bytesToSamples(6401) has a defined, documented result (recommend rejecting odd counts via optional or a precondition the caller cannot violate because the ring is frame-based); chunkSamples with a 0 argument returns a value the drain loop treats as fatal, not as a loop condition; peakAmplitude({}) == 0; and a heap-allocated pump, deliver 10, delete, processEvents, no crash (meaningful under ASan).
- **[Low]** The "pptv_tests must never link pptv_voice" property — described by the design as the mechanical enforcement of the entire testability constraint, "a security property, not an oversight" — is enforced only by a code comment. The proposed CI plan adds two greps (partial_result, set_grm) but not this one, even though this is the higher-value guard: the two greps protect against a specific API misuse, while this line protects the whole pure/IO seam. A single well-meant `target_link_libraries(pptv_tests PRIVATE pptv_voice)` added to make one integration test compile would silently make it possible for ctest to open a device, and CI on a runner with no microphone would still pass.
  - *fix:* Add a third CI grep next to the other two: `grep -qE 'pptv_voice|Vosk::vosk' tests/CMakeLists.txt && { echo '::error::pptv_tests must never link the voice engine — see the seam contract'; exit 1; }`. Three greps, same step, same rationale.
